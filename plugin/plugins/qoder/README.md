# Uta Desktop Companion for Qoder

让 Uta 桌宠跟随 Qoder 的工作状态，并允许 Qoder 里的模型主动控制角色表情、动作和气泡。

## 前置条件

先启动 Uta 桌宠（桌面上的 `Uta` 快捷方式，或 `start-uta.bat`）。桌宠没开时，本插件不会报错，只是安静地不产生效果。

## 安装

### Qoder 桌面版

1. 打开 **扩展 → 插件**，点右上角 **添加插件**；
2. 选择 **上传插件**，指向 `uta-qoder-plugin.zip`；
3. 安装后在 **已安装** 里确认出现 `Uta Desktop Companion`；
4. 如果状态没有立刻生效，重启一次 Qoder（插件里的 hook 需要重新加载）。

### Qoder CLI（已安装 CLI 时）

```powershell
qoderclicn plugins install <解压后的插件目录>
qoderclicn plugins list
```

安装后在 CLI 里执行 `/plugins reload`，或重启 CLI。

## 从桌宠向 CLI 会话发送文字

桌面版仍请回 Qoder 输入。CLI 请用随包启动器打开，它会记住本次程序和配置目录，不修改系统环境变量：

```powershell
node "<插件目录>/runtime/launch-qoder-cli.mjs" --uta-exe "<qoderclicn.exe 的绝对路径>" --uta-config-dir "<已有 CLI 配置目录的绝对路径>" -- --cwd "<项目目录>"
```

启动器会为该次 CLI 加载本插件。在 CLI 中发送一条消息后，Uta 的“连接与会话”会显示发送是否就绪。这是待真实宿主验收的 CLI 试验通道；只在会话明确空闲时可用。文字会续跑你选定的会话，沿用登记的工作目录、配置和权限模式；发送时避免在 CLI 中同时续跑。缺失登记时会说明原因。

命令行支持依据：[Qoder 参数](https://docs.qoder.com/cli/cli-reference)、[脚本模式](https://docs.qoder.com/cli/run-in-scripts)。本版已通过隔离程序/模拟回执检查，真实账号下的续跑和画面仍需验收。

## 它会做什么

**状态跟随**（自动，不需要模型调用）：

| Qoder 事件 | 桌宠表现 |
| --- | --- |
| 会话开始 | 待机；如果桌宠被隐藏，会重新呼出（可在 Uta 设置里关闭） |
| 你提交提示词 | 思考 |
| 调用工具前 | 专注（显示工具名） |
| 工具完成 / 失败 | 继续处理 |
| Agent 回复结束 | 完成（开心一下） |
| 会话结束 | 待机 |

**角色工具**（模型可主动调用）：显示并朗读气泡、切换情绪、应用状态预设、播放动作；`deskpet_get_capabilities` 会返回当前模型可用的情绪与预设分组。模型只在它认为值得打扰你时使用这些工具，而不是把每一步输出都转发过来。

「会话开始呼出」只会把已经运行的桌宠窗口带到前台，不会替你启动 Uta，也不会抢键盘焦点；不想每次被叫出来，可以在 Uta 的 **设置 → Agent 工作型宿主 → 宿主启动时呼出桌宠** 关掉。

## 审批卡片

Qoder 在真正执行敏感操作前会发 `PermissionRequest`。本插件会把这次请求转成桌宠上的「批准 / 拒绝」卡片：

- 点 **批准** → Qoder 继续执行（allow）；
- 点 **拒绝** → Qoder 停止这次操作（deny）；
- 桌宠没开、60 秒内没点、或请求被取消 → 插件**不输出任何决策**，Qoder 会照常弹出它自己的审批框。宁多多问一次，也不会静默放行；
- 权限模式本身是 bypass 时，不会打扰桌宠。

卡片上会显示工具名，以及命令/文件路径的摘要（最多 300 字符，只在本机显示，不上传）。

## 桌宠什么时候说话

状态是自动的，说话是模型决定的：

- **工作状态**（思考、执行工具、完成、出错）继续自动同步到桌宠，不需要模型开口；
- **气泡内容**只在模型主动调用桌宠工具（如 `deskpet_notify`）时出现。提示里要求模型只在关键发现、需要你知道的结果或最终答复时说话，通常一轮 1–2 条、每条 1–2 句；
- 如果模型整轮都没有主动说话，Qoder 结束时只补**一条**短摘要兜底，避免完全没反馈；
- 模型已经主动说过话的回合，结束时不会再补摘要。

插件不再读取 Qoder 的 transcript 来自动搬运工作正文，因此工具边界不会连续弹出一串气泡，也不会把历史面板里的旧对话当成新汇报。

## 已知限制

- 审批接管依赖 Qoder 接受 `hookSpecificOutput.decision.behavior`。若宿主忽略该决策，会自动回退到 Qoder 自己的审批弹窗，不会静默放行。
- **实测：桌宠上的批准/拒绝会生效，但 Qoder 自己的权限弹窗仍会出现在前台，需要再点一下关闭。** 这是宿主 UI 的行为，插件无法从输出里抑制；操作本身已经按桌宠的决定继续，不会等宿主弹窗。
- 桌宠气泡不再逐字流式显示完整回复；需要完整内容时请回 Qoder 窗口查看。

## 排查

- **桌宠没反应**：先确认 Uta 正在运行（托盘有图标）。插件对宿主永不报错，失败是静默的。
- **查看事件是否到达**：`%APPDATA%\uta\hooks\qoder-events.jsonl` 会记录每个事件的**字段名和工具名**，不记录你的提示词或工具参数。文件超过 256 KB 会自动重建。
- **Hook 没触发**：确认 Qoder 设置里已启用本插件；改动 hooks 配置后需要重启 Qoder。
- **Node 不在 PATH**：`hooks/hooks.json` 里的 `command` 默认是 `node`。若你的环境只能用 Qoder 内置 Node，可把它改成 `${QODER_NODE_RUNTIME}`（`mcp.json` 里已经这么用了）。

## 卸载

在 Qoder 的 **扩展 → 插件 → 已安装** 中移除本插件即可；不会改动 Uta 的任何模型或配置。
