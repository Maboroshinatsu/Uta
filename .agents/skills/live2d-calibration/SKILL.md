# Live2D 视觉标定与动作调试

先用真实画面确定控制关系，再编排一个动作。参数存在、实际写入、可见影响、自然程度是四种不同证据，分别记录。

## 试验入口

Uta 工作区通常在 `D:/Frankenstein/Uta`。先读仓库协作规则、当前代码和运行实例，遵循用户本轮范围。使用仓库的 `app/scripts/live2d-lab/`：先读该目录 README，再用独立 appData/profile、复制的模型和私有 runtime 启动实验。工具会生成 rig-info.json、请求/渲染读数、原图和录屏。不要为观察动作修改日常模型、宿主配置或日常数据。

已验证的大肥鱼结论见 [references/dafish.md](references/dafish.md)。仅在模型签名相符时参考；更换模型后重新标定。

遇到能力档案缺失、物理联动或批量切模时，读 [跨模型标定](references/cross-model.md)。

## 标定

1. 取得当前实际参数 ID、范围、默认值、物理输入/输出连接和部件可见性。不要凭通用参数名创造缺失通道，也不要把物理输出当成主动输入。
2. 切模后确认台上只有目标模型，交叉淡化结束且有新帧。固定镜头，暂停视线与随机动作，隐藏气泡，保留物理。对比重复基线和回归基线；局部有漂移或遮挡时，只判读稳定区域。
3. 每次只改一个输入，等待当前试验实际推进渲染帧，再记录截图、物理前读数与渲染前读数。Cubism 在 update 后会恢复 saved parameters。工坊滑块另外测中位到端点、负端直切正端和复位，分别记录 UI 值与渲染值。单向控件测中间值和端点。
4. 区分 input 与 output 试验：物理前写入用于识别实际播放链路；物理后强写用于定位底层形变。只有强写有效时先找覆盖原因，不能直接宣称正式预设可用。
5. 无明显变化时测试有依据的上下文：手型开关、衣物/部件、其他关节、眼开度等。相关关节保持完整 reference，只改变一个变量，并与同上下文 reference 比较。用“该上下文未观察到变化”，不要写成“无效参数”。
6. 查看原图的身体、手、脸等局部。像素变化和包围框用于筛选，不能评价美感；嘴角、眼形等细节会被全身阈值漏掉。记录模型资源签名、条件、数值、截图和不确定性。

## 编排与迭代

- 先形成起点、中间姿态和终点。终点好看不代表路径合理：至少检查抬手/收手途中 5–7 个姿态，再决定曲线与时序。
- 一次只解决明确问题，保留 A/B。先在常用显示尺寸下把身体重心与主要关节做到清楚可辨，再收敛幅度并加入视线、脸部和物理跟随。自然不等于幅度小或速度慢；不要把日常微动作的克制标准套到明确的开心表演上。开关不等于动作；不要在两套手臂姿态分离时慢慢交叉淡入。
- 对含独立身体输入的动作做头部中位对照，记录头部渲染读数和肩以下的画面变化。仅能联动时，记录可用输入及其限制，再编排头身动作。
- 记录完整一轮和循环接缝，检查关节轨迹、速度突变、穿插和脚底漂移。分别测试关闭工坊和被下一动作打断，核对 Cubism 队列是否停止、参数是否按收尾模式恢复，并观察是否在下一循环重新启动。
- 最后在没有实验覆盖钩子的干净实例里，使用 Uta 正常 Cubism 播放、参数所有权和物理验证。实验强写成功或命令 accepted 不代替该步骤。
- 保存动作数据与标定记录，保留用户要求的旧版。只将本轮实际验证的方法/结论补入技能；不要自动扩展其他状态、通用框架或 VTS 接入。

## 交付

提供一个可直接比较的动态预览，简述本轮实际改善和仍存在的问题。注明已验证的覆盖范围、正式播放与停止情况，以及新版本的入口。把客观标定结果和主观观感分开，最终情绪表达与审美仍由用户反馈确认。
