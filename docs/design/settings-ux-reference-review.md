## 已提取并用于 Uta 的增量

文章第三、四、六节对本次最有价值的是：把反馈时机、依赖关系和检查步骤写进任务；一份主控计划、一名实现者、独立审查；实际操作验证后再确认完成。这些方法与现有多 Agent 工作流一致，新增工作应落在以下具体行为，而不是再建一套并行流程。

| 来源与方法 | Uta 的具体落点 | 可判定的验收 |
| --- | --- | --- |
| 文章第三节：明确校验时机 | 连接/语音字段首次输入不立即报错，失焦或测试/保存时检查；出现错误后修改即更新 | 半个地址不弹红屏；失焦提示具体原因；失败不清空表单 |
| 文章第三节：联动与旧结果 | 服务商/模型/会话变更后使相关验证结果失效；请求关联 scope、draftRevision 和 attemptId | 测试 A 晚于 B 返回，当前表单仍只接受 B；B 的错误不被 A 的成功擦掉 |
| SPT 整体流程：统一规范先行 | Antigravity 先交设计 token、组件状态表和一张代表性的语音配置页，再复制到六领域 | 同一字段/按钮的正常、焦点、错误、禁用状态一致；不用六页同时铺开后再返工 |
| SPT 任务反馈：业务证据分开 | 本地校验、服务测试、配置保存、运行生效分别反馈；超时明确结果待确认 | 不用倒计时制造成功/百分比；失败只重试当前服务，不重复保存其他页或重复收费合成 |
| SPT 可逆编辑：按操作分组 | 工坊一次 pointerdown→pointerup 的参数拖动只记一条撤销；预览不覆盖草稿 | 一次拖动撤销一次，取消/无变化不新增历史；换模型不能恢复旧快照 |
| SPT 命令入口：输入与执行分开 | 设置搜索只导航；以后增加动作命令时再加执行契约。中文候选确认、快捷保存和 Enter 分开 | 输入法组字/候选确认不触发保存或播放；搜索高亮不自动执行动作 |
| 文章第四节：一份已确认计划 | 本方案为唯一执行入口，Antigravity 报告经过主控裁决后归档 | 执行方任务单写明保留行为、文件归属、失败路径和真实检查，不自行合并或发布 |

不引入文章里的业务系统示例 API、React 专用规则、接单/营销内容；不因资料有 27 个主题就添加 27 种效果。普通设置保留稳定文字/表单，复杂动画只用于有用的状态变化。录音条如果以后增加，必须来自实际采集状态，不能用随机波形冒充。

## 统一视觉交付：从线框到可用界面

当前线框用于确认结构，不能算最终视觉稿。下一份 Antigravity 设计交付应包含：

1. **少量全局 token**：按用户最新要求保留蓝色大色块，呼应项目图标，分别定义 surface/text/border/accent/error/focus，见 [蓝色规范](blue-block-design-spec.md)；系统中文字体，正文约 14px，辅助文字 12–13px，控件通常 36–40 DIP。深浅主题同样覆盖 disabled/error/focus，不只是改背景色。
2. **基础组件状态表**：SettingRow、Field、Switch、单选/下拉、状态摘要、消息提示和草稿操作栏共用规则；不要每页重新发明胶囊、阴影和保存条。
3. **代表页先行**：先完成“语音 → 播报配置”的高保真可操作样页，含关闭摘要、编辑草稿、检查中、失败保留输入、保存结果；再做“角色与动作”和工坊。当前原型已增加本地模拟失败/重试，以评审交互，明确不联网、不落盘。
4. **对照检查**：在同样内容下检查常规窗口和窄窗口、长名称与错误文案、键盘/中文输入法；结构不通过时先修，不靠缩字或动画遮挡解决。概念图或 Skill 建议不代替实际排版与交互。

## Windows 窗口行为：用户要求与建议基线

这里的“任务栏”指 Windows 任务栏，区别于系统通知区域的托盘。用户要求的主要恢复入口是任务栏。两个窗口仍属于同一 Uta 应用；系统是否把它们分组/展示缩略图由 Windows 设置决定，不承诺两个固定独立图标。

| 操作/事件 | 桌宠 | 设置中心 | 后台/草稿/恢复 |
| --- | --- | --- | --- |
| 打开设置 | 保持当前可见或最小化状态 | 创建/定位唯一设置窗口 | 打开设置不能顺便 restore 桌宠 |
| 点击“最小化桌宠”或任务栏最小化 | 走真实 minimize，保留任务栏入口 | 不变 | 连接/会话继续；停止无必要的光标轮询与视觉刷新，不写默认设置 |
| 点击桌宠任务栏窗口/“显示桌宠” | restore 到原位置，回到既有窗口 | 不变 | 清除手动最小化意图；不加载第二份模型 |
| 点击设置的最小化 | 不变 | 标准最小化到任务栏 | 草稿与编辑租约仍属该设置会话；不能当作关闭或保存 |
| 点击设置关闭按钮 | 不变 | 有未保存修改时走守卫，否则关闭 | 结束该工坊预览/释放租约；不退出 Uta，不销毁桌宠桥 |
| 手动最小化后收到普通宿主活动/回复 | 默认保持最小化 | 不变 | 保留消息与工作状态；自动呼出设置不得覆盖本次明确的手动最小化 |
| 最小化时有待审批 | 默认不强制 restore/focus | 不自动新开/跳页 | 保留待处理审批，任务栏有限提醒/托盘备选入口；绝不自动同意，超时按现有宿主契约 |
| 显式“隐藏到托盘”（次级操作） | 隐藏，与最小化分开 | 不变 | 托盘可显示桌宠/打开设置；首版可以不扩大此功能，只保留现有兼容入口 |
| 显式“退出 Uta” | 结束 | 全部关闭 | 先处理未保存守卫与待决请求，再关闭桥、音频与快捷键；真正退出不复活窗口 |

推荐将用户意图记录为窗口会话中的状态，区分用户最小化、系统状态变化和应用自动恢复；直接使用布尔 isVisible 不足以解释全部情况。首版不把最小化状态跨重启持久化，不把启动后的隐藏当作用户永久偏好。打开/恢复设置和桌宠分别发命令，禁止共享旧“显示/隐藏”切换按钮误作用于两个窗口。

审批“只提醒不自动展开”属于配合用户最小化要求的新建议，将改变旧的强制置顶行为；实施时必须验证不丢审批、不默认批准，不能把它当作纯样式改动。首版不增加通知权限/系统通知/第二个审批界面，以任务栏提醒和既有托盘恢复通道为边界。

TTS 继续服从已有播报开关，最小化不隐式改成静音。正在录音时的最小化策略须在窗口任务中定清：建议首版停止主动采集并明确反馈，避免隐藏采集；不自动提交未完成录音。已在处理的识别/合成结果按命令身份隔离，不因关窗口错误回灌。该策略是实现前待验证约束，不声称现有 API 已具备完整能力。

## 源码核对与实现缺口

`main/index.ts` 创建桌宠已设 `skipTaskbar:false`；`preload.minimizeWindow` 和 `minimize-window` handler 已有，且隐藏/最小化时会停止光标轮询。因此是补入口、改窗口生命周期和恢复策略，不是从零发明最小化。当前仍需处理：

- `summonPetWindow` 会 restore，需尊重手动最小化意图。
- `presentApprovalWindow` 会 restore、置顶并 focus，需改为用户认可的提醒策略。
- `close-window` 固定关闭 mainWindow，不能复用于设置的关闭按钮。
- 新设置窗口必须是独立、非模态 BrowserWindow，不设置会导致一起最小化/置顶的父子依附；窗口引用/关闭守卫与 sender 权限分别处理。
- `window-all-closed` 当前非 macOS 会退出；保持常驻窗口/明确退出状态，避免将新设置的关闭错误解释为整个应用退出。
- 任务栏提醒的 `flashFrame`、`minimize/restore` 在本机 Electron 34 类型中存在；具体系统行为仍需 ZIP 解压版实测。参见 [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window#winflashframeflag)。

第一批产品实现建议先锁设置/窗口命令契约，再在独立 profile 做“打开设置 → 最小化桌宠 → 操作/关闭设置 → 任务栏恢复”的最短闭环，随后迁移代表页。不得把单文件原型里的窗口示意称为 OS 最小化已经实现。

## 新增验收场景

- 最小化桌宠后设置保持可用；关闭设置后 Uta 与连接仍在，点击任务栏可恢复原角色/位置。
- 手动最小化后宿主启动、回复和审批不强制弹回桌宠；审批可恢复处理，不被静默同意或丢失。
- 不把任务栏与托盘混称；Windows 合并图标时仍能辨认桌宠与设置窗口标题。
- 语音草稿测试失败保留字段；局部重试不重写其他页；修改地址/服务商后旧成功立即失效。
- 工坊一次连续拖动只产生一次可撤销操作；取消不提交；中文候选确认不误保存/播放。
- 设置最小化、设置关闭、普通导航、应用退出四条路径分别验证草稿/预览租约，不能仅测“点右上角”。
