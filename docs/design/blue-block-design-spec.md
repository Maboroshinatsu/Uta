# Uta 蓝色大色块：设置中心设计规范

日期：2026-10-23。用户最新要求优先：保留大色块，蓝色呼应项目 icon。此规范替换旧线框的陶土强调色与偏暖灰绿视觉方向；六领域、双窗口和保存语义继续有效。演示：[设置线框](settings-ux-wireframe.html)。

## 1. 视觉目标

已实际查看 `app/src/renderer/public/icon.png`：浅蓝、灰蓝/靛蓝、奶白和少量肤粉是主要视觉印象。设置应与这个角色图标属于同一产品，但不是把插画所有颜色等比例搬到表单。

采用“清爽蓝色工作台”：连续的大面积蓝色导航与角色区域提供辨识度，主内容区保持明亮可读，文字/操作层级明确。蓝色面积通过完整区域形成，不通过几十张小蓝卡凑出来；避免每组字段都嵌套三层卡片。

## 2. 初始 tokens

这些是根据图标选择的界面候选色，并非声称每个值都精确采样自像素。正式组件实现要校验实际文字尺寸/颜色组合的对比度。

| token | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| brand-block | `#78A6E5` | `#28497B` | 大面积品牌导航/角色区；浅色上使用深蓝文字 |
| brand-soft | `#DDEAFF` | `#233650` | 选中项、上下文底色与次级蓝区 |
| action | `#2457A7` | `#A8CAFF` | 主要按钮；浅色配白字，深色配深色字 |
| ink | `#1C2D49` | `#E7EEFA` | 正文与标题 |
| secondary | `#526580` | `#B1BFD4` | 说明与次级标签，不能低到读不清 |
| canvas | `#EDF3FB` | `#111B2B` | 窗口外底/背景 |
| surface | `#F8FAFE` | `#19263B` | 主工作区 |
| input | `#FFFFFF` | `#202F48` | 可输入/可编辑内容 |
| separator | `#C5D3E8` | `#455979` | 分隔/边界 |
| focus | `#174B9A` | `#B8D5FF` | 清晰的键盘焦点环 |

成功绿、警告琥珀、错误红只表达状态，并同时给文字/图标，不只靠颜色。不要为了全蓝主题把失败也显示蓝色。浅品牌蓝配白小字往往对比不足，默认使用深蓝文字。

## 3. 大色块怎样使用

- 左侧导航是一整块蓝色区域，品牌/六项导航/实例提示在同一色块中；当前项以浅色面和明显文本标出。
- 角色页的当前角色区域是完整的宽色块，角色信息与“更换/表现设置/动作库”有明确层级；不把每个统计拆成迷你卡。
- 其他页面顶部可使用低饱和蓝色页头，说明当前任务和配置上下文；表单本体仍是清楚的行与段落。
- 工坊可用深蓝侧栏和浅蓝舞台占位区强调工作模式；不为美观在设置里加载第二个模型。
- 主要蓝色操作每个任务区通常一个；保存/播放并列时视觉上区分，不能都显得像“完成并保存”。

品牌区的比例是设计手段，不设机械硬百分比。1280×720首屏应能明显感知蓝色块，仍能一眼找到当前页、主要操作和修改状态。

## 4. 排版、密度与布局

默认设置窗口建议 1120×780，最小可用目标 960×640；低分辨率适配到可用工作区，不能窗口高于屏幕。系统缩放125/150%、中文长文本必须实际检查。线框窄窗口仅用于布局压力测试，不宣称产品支持手机。

侧栏200–224px；内容宽度按任务控制，常规表单可读宽约720–840px，工坊利用完整空间。内容内边距24–32px；主要段落间24–32px，设置行12–16px。正文14px起，辅助12–13px需对比足够；不靠普遍缩到11px解决拥挤。

标题26px左右，分组16–18px，字段标签14px。图标配文字，禁止只有模糊小图标才能打开关键功能。正常按钮点击高度36–40px；主要操作40px；焦点环不被overflow裁掉。

复杂页面使用稳定“标题→摘要→分组→字段/操作→局部结果”。长表单让内容滚动，页面导航和必要的草稿保存区可固定，但不能遮住最后一行。没有草稿的即时偏好不显示假的全局“保存全部”。

## 5. 组件状态与操作语言

| 组件 | 必备状态/行为 |
| --- | --- |
| 设置行 | 标签、简短说明、控件、当前值；说明不挤在开关两边；禁用写出原因 |
| 服务表单 | 未修改/已修改/校验错/测试中/保存中/失败/已保存；切provider保留各自草稿 |
| 测试按钮 | 说明使用草稿还是已保存值；可取消；成功仅说明测试结果，不隐式保存 |
| 能力摘要 | 已连接/未绑定/能力缺失/不可验证分开；不能绿色“桥可达”掩盖宿主未连接 |
| 模型能力 | “可用”“需校准”“模型不支持”与理由；不显示不存在参数的有效滑块 |
| 工坊 | 当前动作、选中步骤、修改标记、撤销/重做、预览/停止、保存/另存为 |
| 结果反馈 | 就近显示错误和重试，输入保持；toast只作辅助，不把关键失败放成转瞬提示 |

用户文案用“表现强度/说话动作/自然程度/恢复日常”，高级工具才显示VAD/FACS/owner。开发profile持续可见，正式用户页面不堆路径/协议名。中文输入法composition期间不触发Enter提交/快捷键。

## 6. 动效

界面切页/展开只做短促150–200ms透明度/轻微位移，取消可中断，reduced-motion可关闭。保存/错误反馈优先可读。大色块保持稳定，不做永久呼吸渐变/全屏漂浮背景抢角色注意。

Live2D本体动效另由表现系统决定；不能用设置按钮的弹跳掩盖角色动作问题。静态原型不作为动画体验证据。

## 7. Antigravity的交付要求

先做tokens、设置行/表单状态与“语音”代表页，再做角色与表现代表页。提供深浅色/125%缩放/失败/窄窗截屏、交互说明与fixture。确认后扩到六领域，保留已有功能迁移清单。

禁止只交首页好看截图；要能说明真实保存时机、错误恢复、键盘路径与缺能力状态。先用fixture，存储/执行接口未合入时不得自行复制Pinia或虚构API。

## 8. 本轮原型范围

仅更新单文件线框的蓝色大区域与主题；虚构数据、无网络/保存/设备调用的限制继续有效。它不代表正式组件库、窗口最小化、设置存储或Live2D改造已经实现。视觉验收截图另附在本轮交付记录。
