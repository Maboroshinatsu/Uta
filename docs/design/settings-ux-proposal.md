## 1. 推荐方向与产品定位

Uta 的设置应围绕“管理我的桌宠与它连接的服务”组织。MaiBot 是可连接的平台之一；云/本地语音是可替换的服务；预设工坊是制作工具。用户无需先理解适配器、运行时桥或 SDK 才能完成操作。

推荐 **桌宠快捷区 + 独立设置中心 + 设置中心内的工坊工作区**。默认两个系统窗口：桌宠、设置中心；工坊占用设置中心的专用布局，不再多开第三个窗口。消息记录和输入仍留在桌宠旁，不搬进设置。

用户已确认桌宠应可最小化，仅保留任务栏恢复入口，设置中心继续独立操作。任务栏与系统托盘区分；普通宿主活动默认不推翻手动最小化，审批保留并提醒而不自动批准。完整窗口状态与当前源码冲突见参考补充，不把已有 minimize API 误报为已经有完善产品入口。

- 桌宠快捷区：解决几秒钟内完成的操作，如切换常用表情、静音、恢复日常状态、打开设置。
- 设置中心：解决换角色、连接平台、配置语音、桌面行为和诊断；可以正常调整窗口大小、切换页面、键盘操作。
- 工坊工作区：解决选预设、编辑动作步骤/部件/参数、预览、保存；具有明确的草稿与编辑会话，不依赖面板是否展开来决定编辑锁。

继续使用 Vue 3、Pinia、Electron 和现有角色/宿主能力契约。允许重构布局、组件边界与状态归属，不建议为了改设置改用其他前端框架。完成设置读写基础后再接独立窗口，不能把两个 Pinia 实例当作共享内存。

## 2. 现状证据与根因

基线 `21583ac`。Codex 已读实际组件并查看独立候选 profile 的真实 Electron 页面；该候选源码与当前产品代码相同。Antigravity 的独立审查另附，不能将其源码审查称为 GUI 验证。

| 已核实的现状 | 用户后果 | 设计处理 |
| --- | --- | --- |
| settings-panel.css：宽 328px，高最多 520px，内容区约 465px | 简单浮窗承担复杂设置；窄列放更多胶囊后频繁换行 | 快捷区保留窄尺寸；完整设置移到可调整窗口 |
| 实测该任务 profile 的设置内容高 2688px，七个主要段落；首段约 538px | 一页接近六屏；找模型/连接须经过主题和语音 | 分任务导航，单页只解决一个目的；此数据受当前配置与诊断展开状态影响，并非所有用户固定值 |
| SettingsTab：主题、窗口、性能、快捷圆点、TTS、STT、模型、两类宿主、诊断串联 | 分类按新增时间/实现归属增长，用户难猜入口 | 重新分六个领域；内置与第三方连接统一目录 |
| TtsSettingsSection：播报关闭仍完整展示云配置；多个字段只用 placeholder | 禁用时仍占空间，填入后看不出字段名称 | 关闭态保留摘要与“配置”；配置使用永久标签和条件展开 |
| TTS 的 watch 会约 600ms 自动保存非密钥字段，另有“保存云端配置”；试听先执行保存 | 不知道何时落盘，试听意外改变配置 | 网络服务采用草稿/测试/显式保存；试听不隐式保存 |
| AdapterPluginSettings：update 调 setPluginSetting；底部“应用并重新连接” | 字段已保存但用户以为仍可取消 | 按服务为单位编辑草稿，提交时才持久化 |
| SettingsPanel 的 saveCurrentCombo 保存后 triggerPreset | 保存与播放绑在一起 | 保存只保存；预览、播放为独立动作 |
| 分组胶囊主体播放首项、箭头展开，钉常驻改变恢复基准 | 选中、播放、编辑、默认状态混用 | 库里点击只选中；显式播放/编辑/设为日常状态；快捷区允许直接播放 |
| 删除、恢复默认、清空还原并列；removeCustomPreset/onRestoreDefaultPresets 直接操作 | 误触影响不易预料 | 明确命名与范围、可撤销；批量恢复先备份并确认 |
| 编辑数据和动作大量留在 SettingsPanel，通过 provide 共享；关闭面板直接解锁 | 视觉拆组件并未解开编辑状态生命周期 | 工坊有独立 draft controller 和 preview session，退出策略统一 |
| host-status 只返回 runtimeEndpointReady/rendererReady 等本地状态；hook 适配器 connected 依据近期活跃 | “服务正常”“在线”容易被理解为插件已加载、会话已绑定、能发送消息 | 按证据展示本机服务、接入、会话、能力，各层不互相代替 |
| 当前 HostCapabilities 已分 sendInput/characterTools/sessionSelection 等 | 仍按平台名字猜功能会显示无效操作 | 根据能力展示，未知/未验证与不支持分开 |

另有一个必须先修正的能力来源问题：hook 型适配器的 `sendInput=false` 不代表整个产品无反向文本能力。`DeskpetStage.sendText` 会在适配器发送失败后调用 `utaAPI.sendHostMessage`；`main/host-bridge.ts` 已有 Codex queue、DSH native/headless、Claude Code/ZCode/OpenCode 路径。新能力视图必须汇总实际文本桥实现、可执行依赖、会话与忙状态；不能只用当前适配器布尔值屏蔽这些功能。代码有实现也不代表本轮已逐平台端到端验收。Qoder/Antigravity 的开发 CLI 派单不等于产品内反向文本通道。

完整旧页面截图和量测保存在仓库外 `operations/settings-ux-20261023/`，不含个人配置或端点正文。当前测试 profile 的 TTS 未启用、STT 未启用；截图仅证明该状态下的布局，不等于全部错误/键盘状态已实测。

## 3. 方案比较

| 方案 | 优点 | 代价/限制 | 结论 |
| --- | --- | --- | --- |
| 保留 328px 浮窗，仅加折叠/搜索 | 工程成本低，沿用当前舞台实例 | 小屏仍多层展开；复杂表单、工坊、键盘与缩放受限 | 可作短期入口整理，不作最终方案 |
| 在桌宠透明窗口内做加宽面板 | 复用当前 Pinia/舞台，过渡快 | 受桌宠窗口边界、位置、穿透/置顶与拖动影响；后台 UI 仍易和角色抢空间 | 可作开发中间态，不能以“加宽”作为验收终点 |
| 独立设置中心，工坊为其中独立工作区 | 空间/导航/恢复窗口位置/键盘符合桌面习惯；设置可脱离角色边缘位置 | 必须先处理多窗口状态、IPC 与单一持久化来源 | 推荐目标；明确依赖后分期落地 |

不采用每个领域各开窗口，也不将全部问题变成十几个顶部标签。复杂性由任务边界和默认折叠来消化，不靠缩小字体。

## 4. 导航和信息架构

设置中心初次打开默认“角色与动作”；以后恢复上次页面和滚动位置。导航为六项，栏目名不采用“面板设置/第三方适配器”等实现名。顶部为页面标题与当前上下文，左侧为文字导航和搜索；非正式 profile 在窗口标题与底部持续标明“开发实例”。正式环境详细路径只放“关于与诊断”。

| 一级页面 | 二级内容 | 首屏应回答的问题 |
| --- | --- | --- |
| 角色与动作 | 当前角色、角色库；动作库；工坊入口 | 我用的是谁，怎样更换，怎样播放/制作动作？ |
| 连接与会话 | 平台目录、选中平台详情、会话与能力、接入帮助 | Uta 正在跟哪个平台/会话工作，哪里没接上？ |
| 语音 | 语音播报、语音输入 | 能否说/听，使用哪个服务，怎样测试？ |
| 桌面与交互 | 窗口行为、角色互动、快捷操作/快捷键说明 | 如何摆放、穿透、跟随和待机，怎样恢复操作？ |
| 外观与性能 | 主题/强调色、刷新率/空闲降帧 | 界面怎样显示，如何降低占用？ |
| 关于与诊断 | 版本与运行实例、连接详情、数据位置与恢复入口 | 我启动了哪份，问题在哪，怎样安全恢复？ |

工坊是“角色与动作 → 选中预设 → 编辑”进入的专用路由，隐藏常规设置侧栏换成动作库/步骤/属性布局，顶部始终有“返回动作库”和草稿状态。它不是第七个常规设置分类。

搜索索引页面/字段/别名（如朗读、音量、TTS、语音识别、STT、后端、穿透、FPS）；结果显示页面路径、字段名称和简短说明，选择后跳到字段并保留焦点。关闭的功能可以被搜索到，不为命中搜索而自动启用。未加载插件的自定义字段不预造空表单。

### 现有功能迁移清单

| 现有功能/入口 | 新归属与操作 |
| --- | --- |
| Live2D/静态立绘模式、当前模型、模型列表、刷新/打开目录、重载 | 角色与动作 → 角色库；模式随角色类型说明，只有存在对应资源才提供选择；刷新与重载放次级操作 |
| 快捷圆点模型栏 | 改为有标签的“换角色”入口；自定义圆点行为迁到桌面与交互 → 快捷操作，旧偏好映射保留 |
| 预设分组/变体、随机组播放 | 角色与动作 → 动作库；分组/筛选、明确播放/随机播放按钮；快捷区只保留常用集合 |
| 钉为常驻 | 动作库 → “设为日常状态”；说明临时动作结束恢复到它；徽标区分日常基准与当前正在播放 |
| 删除、恢复初始、清空还原 | 删除移到项菜单并可撤销；“恢复模型默认动作”与“重置当前姿态”分开，均说明影响范围 |
| 陪伴节拍/原生动作 | 动作库 → 原生动作；用户文案“原生动作”，按当前模型能力提供；不能把所有模型都显示成鲸鱼娘的特定道具动作 |
| 工坊新建/重命名/同名保存、情绪分组 | 工坊 → 元信息与“保存/另存为”；覆盖明确确认，不以名字暗中决定目标 ID |
| 步骤、顺序、过渡/停留、恢复/保持/循环、原生 motion | 工坊 → 步骤区/当前步骤属性；保持现有 durationMs/holdMs/finishMode 数据语义 |
| 部件穿搭、五官眼神、姿态、其他参数、重置参数/部件 | 工坊 → 属性面板，类别筛选/搜索/只看已修改；重置范围可见并可撤销 |
| Agent 宿主、独立运行、第三方适配器 | 连接与会话 → 一个统一平台目录；独立运行是明确选项；内置/扩展作为次级来源信息 |
| 插件字段、目录、应用/重新连接 | 选中平台详情 → 基础连接表单、接入帮助、高级项；插件字段按 schema 渲染，未知字段兜底表单；目录放帮助/高级 |
| 当前绑定、通道描述、MCP/hooks 状态 | 当前平台详情 → 能力与证据分层；本地桥不能冒充宿主连接成功 |
| 宿主启动呼出桌宠 | 连接与会话 → 当前连接行为，标注这是应用级开关；桌面页只提供跳转链接，不再出现第二份开关 |
| 语音播报总开关、回复摘要/状态解说 | 语音 → 播报；总开关在首行，子项使用勾选项；注明默认播报摘要 |
| 本地/云 TTS、服务商、地址、模型、音色、风格、密钥 | 语音 → 播报 → 配置服务；当前 provider 摘要 + 编辑表单，服务商切换后保留各自草稿 |
| 语速、音量、试听 | 语音 → 播报 → 播放效果；独立标签/数值；试听使用明确配置，不隐式落盘 |
| STT 开关、本地/云、服务商、接口/模型/语言/密钥 | 语音 → 输入 → 配置识别服务；“录一段测试”不自动发给宿主 |
| 识别后直接发送、快捷键提示 | 语音 → 输入；自动发送默认关闭，能力不足显示原因；设置不增加未经实现的任意快捷键编辑 |
| 空闲随机动作 | 桌面与交互 → 角色互动，与注视跟随/触摸说明同域；从 TTS 移出 |
| 鼠标穿透、悬停透明、视线跟随 | 桌面与交互 → 窗口/角色互动；穿透只影响桌宠，设置中心始终可操作；给托盘恢复路径 |
| 置顶、拖动、滚轮缩放、双击复位等现有舞台/托盘行为 | 桌面与交互 → 窗口行为/操作说明；置顶调用现有主进程能力，缩放是否增加表单由可复用接口决定，不能伪造已有设置 |
| 日夜主题、预置色、自定义色、圆点切主题/取色 | 外观与性能 → 外观；提供可靠默认配色与键盘可用的颜色名称 |
| 30/60/120/自适应、显示器 Hz、空闲降帧 | 外观与性能 → 渲染；用单选/下拉统一呈现，显示器 Hz 是检测值而非开关 |
| profile、packaged、版本、SHA/dirty、路径 | 关于与诊断，默认摘要；开发实例的身份持续可见，完整路径按需展开 |
| 聊天记录、临时输入、审批、录音状态 | 仍在桌宠交互层；设置只管理规则与能力，不把聊天/审批搬入设置 |

未显示于当前设置的候选功能，如自动备份、数据导入/导出、草稿恢复、可编辑快捷键和设置搜索，均属于新增工作；按下面阶段实施，不能在首版放无法使用的占位按钮。

## 5. 日常快捷区与设置布局

快捷区约 300–340 DIP 宽，按可用工作区限制高度；不含地址/密钥/分镜/诊断表单。建议顺序：角色名称与换角色、当前平台和简短状态、最近/常用动作、语音静音/恢复日常状态，底部“打开设置”。麦克风和消息仍使用既有桌宠工具入口，避免重复三套按钮。

设置中心默认约 960×720 DIP，按显示器 workArea 留边后夹取；尺寸是设计初值，原型评审后调整。目标常规最低布局约 640×480，若高缩放/小屏可用区域更小，以工作区为上限，不能强制最小尺寸把按钮推出屏幕。宽度不足约 820 时将侧栏改为文字页面选择器；工坊属性区切为独立面板，表单不缩字、不挤成三列。不按物理像素固定窗口。

正文采用标题 + 领域分区 + 对齐设置行：左边名称/说明，右边控件；复杂表单使用标签在上。仅为连接状态、当前角色和编辑容器使用有意义的卡片，不给每个开关套圆角胶囊。页面仅一个主要垂直滚动区；工坊的资源列表/属性面板可独立滚动，时间轴可横向滚动，禁止整体横向溢出。

工坊预览优先使用现有桌宠舞台，不再加载第二个 Live2D 渲染实例。工坊显示“预览在桌宠窗口进行”及定位桌宠入口。用户若以后需要内嵌舞台，单独评估模型资源/渲染器转移方案，不能通过复制 Pinia/模型对象实现。

## 6. 关键用户流程

1. **第一次使用**：打开设置看到当前角色；无角色时说明支持的资源类型与打开模型目录。选择连接平台 → 显示该平台实际接入步骤 → 等待插件事件/有效会话。语音是可跳过的后续配置，用户可选独立运行完成初始设置，不强制联网。
2. **换角色**：角色库选择候选 → 展示类型/能力 → 应用并等待加载 → 成功后才更新当前角色；失败保留原角色和可操作重试，不显示虚假的已切换。存在工坊草稿时先解决草稿再启动切换。
3. **接入 Codex/Qoder/Antigravity/DSH/MaiBot**：连接页选择目标 → 查看“当前 Uta 支持的能力”和接入状态 → 按需配置/验证 → 选/绑定可验证会话。无法向该平台发送文本时说明“此版本仅接收角色/状态事件”；不出现必然失败的发送按钮。开发 CLI 派单与产品内文本输入不混为一谈。
4. **启用播报**：语音 → 播报 → 配置本地或云服务 → 字段验证/测试 → 保存 → 启用开关 → 试听。无密钥不假显示就绪；连接失败保留草稿/已保存选择，不静默切服务。修改音量立即生效且可恢复；初次试听有声量预期。
5. **使用语音输入**：语音 → 输入 → 配置并测试录音/识别 → 默认将结果填入输入框；确认当前宿主支持文本发送后才可启用直接发送。测试结果不进入真实会话、不保留音频。录音权限/设备/快捷键冲突各有针对性提示。
6. **做一个新动作**：动作库 → 复制现有/新建 → 进入草稿 → 添加步骤/调参数 → 预览/停止 → 保存或另存为 → 返回库。保存不触发播放。关闭/换角色时提示保存、放弃或继续编辑；有草稿恢复功能后额外提供“保留草稿”，未落地前不承诺。
7. **日常播放与日常状态**：快捷区直接播放常用动作；动作库点选只查看详情，播放按钮执行。设为日常状态有明确当前模型范围；临时动作演完按 finishMode 恢复，不覆盖保存的编辑草稿。
8. **排查“Agent 调用了但桌宠没动”**：连接页显示平台/会话/最近可验证事件 → 展开本机服务/渲染层状态 → 测试角色反馈（用户主动）→ 若有编辑锁，解释“正在编辑，外部动作暂缓”并可返回工坊/结束编辑。不能拿 HTTP accepted 或最近 hook 活跃直接显示“画面已播放”。
9. **误开穿透或恢复默认**：托盘可取消穿透、打开可操作的设置中心；重置姿态不删除预设；恢复模型默认动作先说明仅影响当前模型并备份/确认，不等同于清空全部应用设置。

## 7. 统一保存和生效规则

| 类型 | 规则 | 可见反馈/离开行为 |
| --- | --- | --- |
| 可逆偏好：主题/颜色/音量/帧率/窗口开关 | 操作即提交，进程确认后显示已生效；请求失败回退 UI 并解释 | 不弹全局“保存全部”；连续滑动本地预览，节流提交，结束后确认 |
| 网络服务与插件连接配置 | 按 provider/宿主建立独立草稿；输入不落盘、不重连。测试草稿明确“仅测试，不保存”；保存持久化后才重配服务 | 按区显示未保存/保存中/已保存/失败。切页保留草稿，关闭/换 provider 用统一守卫处理，不把空字符串当删除密钥 |
| 选择当前宿主/角色 | 属于运行命令，检查草稿冲突后明确执行；反馈进行中与最终结果 | 不被任意配置字段输入触发。失败保持用户意图可见，不回退成别的平台或独立运行 |
| 工坊预设 | 独立草稿，显式保存/另存为；预览不保存；保存不播放 | 模型/预设 ID 明确，名称不作为隐式覆盖依据；冲突时可另存或重新加载，不静默覆盖 |
| 破坏性操作 | 删单项优先可撤销；恢复默认/批量替换先备份并确认范围 | 文案如“恢复当前角色的默认动作”，不使用含糊“清空还原” |

测试服务的临时配置与密钥只在受控 IPC 内存传递，不写配置/日志；新增 API 必须提供验证、取消、超时与清理。首版若该 API 尚未实现，不能复用会保存配置的旧试听接口并伪称“仅测试”。

“保存成功”只指持久化成功；“连接成功/试听成功”是另一个结果。例如“配置已保存，连接失败；检查地址后重试”。错误不自动清空表单，不自动改用户选择。密钥显示“已设置/未设置”，留空不修改，清除为明确独立操作；不同服务商的密钥不混用。

## 8. 连接与能力展示：诚实而可操作

当前只知道部分信息。目标视图按证据分层，缺少检测接口的层显示“未验证/无法检测”，不能猜为已安装或已连接：

| 层次 | 现有证据/缺口 | 推荐用户文案 |
| --- | --- | --- |
| 用户目标 | hostPreference/期望绑定 | 已选择 Codex；等待接入。选择不等于在线 |
| 本机 Uta | getHostStatus 的 runtimeEndpointReady/rendererReady | 本机接收服务已启动；画面处理已就绪/尚未就绪 |
| 平台接入 | 当前 hook 活跃探测、实际协议事件；完整安装检测尚无通用接口 | 最近收到平台活动；插件安装未验证；必要时给接入说明 |
| 会话归属 | 运行协议已有 session 绑定，但设置页缺完整列表/操作 IPC | 已绑定某会话/等待会话；列表来自实际运行信息，不能虚构所有平台都能枚举 |
| 可用操作 | 统一视图汇总 HostCapabilities、主进程文本桥实现/依赖和当前会话状态 | 角色动作可用；文本发送不支持/等待会话/忙碌/可用，取消同理；不能仅取适配器的 sendInput |
| 最终反馈 | 桥接受/renderer 消费/动作实际执行是不同证据 | 已接收/因编辑暂缓/执行失败。若无执行确认只显示已有证据 |

统一目录可展示已加载平台与不可用扩展，不要求一屏平铺全部平台按钮。选中平台显示配置、能力和帮助；未选平台不渲染其全部字段。现有 `HostConnectionState` 不宜直接改成十几个枚举；新增只读 ConnectionViewModel 组合各维度，保留服务与适配器契约兼容。

不把 MaiBot 特定地址/概念放进其他平台的基础设置。第三方插件的 schema 支持 label/help/order/group/advanced 等展示元信息为增量能力；旧 schema 仍用兜底表单。未知/加载失败插件保留用户选择和配置，不能 normalize 成 standalone 并覆盖偏好。

## 9. 工坊状态与外部事件

新建/编辑获得带 editorSessionId、modelId、presetId、revision 的编辑会话；舞台拥有预览租约，设置窗口仅发送有界命令。表情/控件修改不能仅靠全局布尔推断所有权。

`浏览 → 编辑草稿 → 预览中 → 编辑草稿 → 保存中 → 已保存`；任一保存失败回草稿并保留内容。切页不自动丢草稿。切模型、删除正在编辑预设、窗口关闭、舞台失联通过同一退出守卫。基本撤销/重做属于工坊范围，至少覆盖改参数/步骤/元信息；不能只依赖“重置全部”。

编辑期间宿主文本/审批继续可见；对当前模型姿态的外部命令拒绝并反馈“编辑中”，不排队重播已经过时的动作。显式预览结束恢复编辑前快照，但前提是仍是同一个模型/preview session，不能把旧模型快照灌入新模型。窗口崩溃/刷新/关闭时释放预览租约；离开编辑不应无限锁舞台。

缩小或后台设置窗口不算结束编辑；关闭规则必须处理草稿。MVP 可以先采用内存草稿+关闭确认；跨重启草稿恢复另有模型/revision 校验和存储白名单，不混入正式预设。

## 10. 视觉、交互与无障碍规范

- 按当前Bento视觉决定使用蓝色强调、柔和表面与清楚分组；保持可读性，不叠加无必要的卡片。连接状态用文字和图标，不只靠红绿颜色；预览/播放/保存使用不同动词。
- 系统中文字体优先，正文约 14px、辅助说明约 12–13px、分区标题 16px、页面标题约 24px；不依赖下载字体。布局间距采用 4/8/12/16/24/32 阶梯，控件高度通常 36–40 DIP，文字标签不挤成省略号。
- 开关用有标签 switch，互斥项用 radio/segmented/select，执行操作用 button，导航不冒充开关。永久 label 对应 input 的 id，placeholder 只举例；帮助不用仅在 title 中出现。
- 鼠标目标优先至少 32×32，常用/触控目标约 40；密集时间轴图标不少于 24 或保证等效间距，按 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)核验。正文对比度目标 4.5:1，重要控件/焦点可见，不以禁用灰字承载唯一错误原因。
- Tab 顺序按阅读顺序；导航/单选可用方向键；Ctrl+F 聚焦设置搜索，工坊 Ctrl+S 保存、Ctrl+Z 撤销。避免新增全局快捷键冲突。焦点进入错误字段，关闭对话框/窗口后回到发起入口。
- Escape 先关闭菜单/次级面板，再走草稿守卫，不一键抛弃编辑；窗口关闭按钮只关闭设置，不退出桌宠。不因外部消息自动跳页或抢焦点。
- 不在滚动/输入/保存按钮上做弹性位移。页面切换可用 120–180ms opacity，减少动态效果模式即时切换；进度/录音保留必要明确反馈。设置首屏不要错峰隐藏字段。
- 先交付一份设计 token/组件状态表与“语音配置”代表页，再扩到所有领域。首次校验在失焦或提交时进行，错误后修正实时清除；错误区域预留高度，避免插入错误文字导致用户刚点击的按钮移位。异步验证关联草稿版本，不能在字段改变后复用旧成功结果。
- 工坊连续拖动按一次完整操作记录撤销，而非每个 input 事件入栈；取消与无变化不新增历史。中文输入法组字/候选确认不触发保存、播放或搜索命令；实际 IME 时序须人工验证，不能仅靠键盘事件单测声称通过。
- 小屏、高 DPI、Windows 文本缩放、深浅主题、长中文/路径/平台名均纳入人工验收。固定底栏不能挡住焦点或末行错误，参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)。

## 11. 工程边界与拟新增接口

以下是目标设计，均需逐项实施核对；不能把名字当成现有 API。

| 模块 | 职责 | 不应包含 |
| --- | --- | --- |
| SettingsCenterShell + navigation registry | 导航/搜索/标题/滚动恢复/窄屏布局/未保存守卫 | Live2D 对象、语音调用、直接 localStorage 写 |
| 领域页面与 SettingRow/FormField | 受控输入、格式化、说明、按能力展示 | 各页各自复制写盘/重连流程 |
| SettingsDraftController | 草稿、校验、dirty、按 scope 提交/失败/冲突与密钥操作意图 | 舞台帧循环或全局连接探测 |
| 主进程 SettingsRepository | 每 profile 单一持久化、schema/revision/原子写、迁移/备份 | 将共享模型旁车作为默认写目标 |
| ConnectionViewModel/运行快照 | 汇总目标、活动、会话、能力、时间戳与来源 | 把最近活动视为完整健康证明 |
| PresetEditorController | 草稿/撤销/步骤/预设 ID/保存冲突/编辑会话 | 面板导航动画、宿主实例创建 |
| 舞台 RuntimeCommandController | 模型/预览/实时表现的唯一执行者 | 另起第二份设置持久化 |
| main settings-window 管理 | 单实例打开/定位/恢复、边界夹取、关闭守卫 | 新增 Uta 桥监听端口或启动第二个宿主适配器 |

新增窗口只加载 settings entry，不挂载 DeskpetStage、不创建宿主适配器、不注册第二套轮询/TTS/STT。设置变更走主进程提交并广播 revision；舞台与设置各自 Pinia 只是视图缓存。禁止利用 file origin 相同/localStorage storage event 冒充有事务保证的跨窗口同步。

建议接口形状：`getSettingsSnapshot(scope)`、`patchSettings(scope, expectedRevision, patch)`、`onSettingsChanged(snapshot)`；语音密钥操作用 keep/replace/clear 意图，响应只给 hasKey；`getRuntimeSnapshot()`/订阅；`requestRuntimeAction(commandId, kind, modelId/sessionId, payload)`/结果；`begin/endPresetPreview(editorSessionId)`。错误包含稳定 code 与可显示的脱敏 message。命令需要超时、防重、取消或明确结果未知状态，不能重复重试引发两次播放。

窗口权限与 IPC 保持 contextIsolation/sandbox、精确 preload API 与 sender 校验。现有 isRuntimeSender 不能粗暴放开给所有窗口；区分 settings sender 可改配置/请求白名单操作、stage sender 可上报渲染/执行结果。设置窗口不得假报 rendererReady 或消费宿主角色指令。Electron 的标准路径参考 [IPC](https://www.electronjs.org/docs/latest/tutorial/ipc) 与 [安全建议](https://www.electronjs.org/docs/latest/tutorial/security/)；具体以项目锁定的 Electron 34 验证，不依赖最新版才有的 API。

## 12. 实施顺序、分工和回退

| 阶段与完整名称 | Owner 与边界 | 依赖/交付/验收 |
| --- | --- | --- |
| 设计定稿：统一规范与代表页 | Antigravity 主设计，Codex 审查 | 独立窗口方向已获认可；先交 token/组件状态、语音配置代表页及错误/焦点状态，再扩展六领域，避免同时铺六页返工 |
| 设置基础：统一存储与窗口契约 | Codex 定 IPC/权威范围，Qoder 实施 repository/draft 的指定文件 | 复用已审查设置迁移设计；每 profile 原子写/revision/备份/迁移和启动 gating；不同 origin 同 profile 一致，不串写、不写模型旁车；先锁接口再并行 |
| 设置骨架：独立窗口与领域导航 | Codex 管 main/preload/entry/sender，Antigravity 只做 Shell/基础组件/领域静态布局 | 单实例窗口、工作区夹取、无重复桥/宿主/模型、退出行为可靠。页面逐域接入，未完成域明确留旧入口，不做空按钮 |
| 领域迁移：角色、连接、语音、桌面外观 | Antigravity 做 UI，Qoder 按拆单做 controller，Codex 接共享状态/运行命令 | 按统一保存规则逐域完成；设置搜索在字段注册后接入。文件所有权固定，禁止同时改同一大组件 |
| 工坊改造：独立编辑会话 | Antigravity 做库/步骤/属性布局，Qoder 做草稿/撤销，Codex 做舞台租约/外部事件边界 | 保存不播放、预览不保存、退出有守卫、失败不丢草稿、换模型无旧快照回灌 |
| 综合验收：多宿主、布局与 ZIP | Codex 审查合并、独立候选打包；DSH 只验 DSH | 全行为/类型/构建 + 真实 GUI/多窗口/打包路径；验收 ZIP 解压 exe 后再由主控提升日常入口 |

不是同时派两个人把 SettingsPanel 继续拆一遍。主控先提交字段注册、类型和接口契约；各任务固定基线、文件所有权和示例响应。Antigravity 负责视觉与交互实现，Qoder 按既定 DeepSeek-Flash/max/1,000,000 请求执行有边界的基础逻辑任务。每批由 Codex 做源码/数据/真实 UI 验收后合并。

旧 UI 在迁移候选阶段保留单一可回退入口，不长期双写；新旧 UI 使用同一 SettingsRepository，不各持一套配置。迁移前备份旧来源，标记迁移版本和冲突；错误进入只读恢复/重试，不用默认值盖掉已有设置。共享模型默认与用户预设分别管理。回退需验证 schema 兼容性，不能只把 exe 换旧后继续读写不兼容数据；正式发布记录数据备份与回退步骤。

### 验收清单

- 每个现有功能在迁移表上有入口、范围、能力条件、保存类型、验证结果；非当前能力不伪装可用。旧字段/模型预设/颜色/密钥/选择不丢失。
- 找到模型、宿主、语音、穿透各自从设置中心主导航最多两次有意义的导航操作可达；不把填表步骤算作导航。首次用户试走 6–8 个典型任务，记录失败/回退而非只问“好看吗”。
- 未启用的语音不会占据整页表单；云字段有永久标签；不同 provider 切换不混用配置/密钥；试听/测试无隐式保存或自动发送。
- 保存失败、IPC 失联、服务不可达、无插件/无会话/不支持发送、录音权限/设备失败、模型加载失败、同名/版本冲突、草稿离开均有可操作状态。
- 100%/125%/150%/200% DPI、可用区域约 640×480 和常规桌面尺寸、深浅主题、长内容、仅键盘走通；无页面水平滚动、底部操作遮挡、焦点丢失、纯颜色状态。
- 两窗口同时操作不会丢更新；重开设置不再初始化旧默认覆盖新值；不存在第二个宿主实例/重复语音/重复桥；关闭设置不退出桌宠，穿透不影响设置。
- 工坊操作、宿主流、切会话、换模型组合通过；当前 288 项应用/104 项插件基线不倒退，新增测试重行为与生命周期，不用源码正则代替结果。
- 干净源码构建 ZIP，在独立目录解压运行 Uta.exe，用候选 profile 走首次启动/导航/语音配置/工坊/关闭与恢复；主控记录哈希、版本与数据备份后才更新日常入口。

## 13. 本轮评审重点
