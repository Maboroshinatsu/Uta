# 设置改为即改即存（2026-10-26）

用户反馈“我都到设置面板改了还要多确认一次”，要求去掉设置页的保存/放弃确认。

## 行为变化

- 12 项公共偏好（主题、强调色、悬停淡出、视线跟随、待机微动作、悬浮球、TTS 开关/引擎/语速/音量/朗读范围）改动即写入本机，不再需要“保存更改”。
- 离散开关与选项立即提交；强调色、TTS 语速/音量等连续控件用 160–220ms 合并防抖，避免拖动时连续刷盘。
- 每次只 `patch` 发生变化的字段，不会覆盖其他窗口刚改的字段。
- 顶部状态提示“正在保存到本机 / 已自动保存 / 保存失败 · 点击重试”。写入失败保留本地值，自动重试一次，也可点状态重试。
- revision 冲突由设置客户端刷新快照后自动重试同一字段（最多 3 次），不再弹冲突横幅。
- 设置窗口与桌宠/快捷面板通过同一设置广播实时同步；在完整设置里切日/夜或强调色，桌面上的快捷面板立即跟随，不再需要保存。
- 关闭保护只保留给即时保存之外的草稿：语音服务密钥和预设工坊。公共偏好已落盘，不再阻止关闭。
- 语音页“保存规则”文案、关于页“保存方式”同步改为即时保存。

## 代码

- `use-settings-draft.ts` 重写为即时写入模型：baseline 跟随已提交文档、draft 保留写入期间的新输入；按字段串行提交、冲突重试、失败重试、防抖合并、`flushPending()` 供关窗等待。
- `use-settings-close.ts` 只在存在密钥/工坊草稿或即时写入失败时提示；关窗前等待在途写入完成；保存并关闭只保存登记的草稿。
- `SettingsWindowApp.vue` 移除保存/放弃按钮、未保存标记和冲突横幅，新增自动保存状态与重试；`AboutDomain.vue` 显示“改动自动保存”；`VoiceDomain.vue` 更新保存规则文案。

## 追加：组合失败修复（2026-10-26）

评估 `ASSESSMENT-2026-10-26` 发现：字段 A 保存失败后，字段 B 成功会把全局状态改成“已自动保存”并清空错误，A 的重试被跳过，关窗直接批准，A 丢失。

修复：`use-settings-draft` 维护逐字段 `failedKeys`；成功只清理本次字段；状态由全部未落盘字段推导；重试计时器只读失败集合；`hasPending()` 包含失败集合与 draft/baseline 差异。关闭守卫在任一字段失败时提示；无草稿时显示“关闭设置前重试保存？”与“重试并关闭”。

验证：新增两条真实 SFC 测试（`settings-window-draft.test.cjs`），反转评估探针后 `status=error / pending=true / 重试再次写入 themeMode / closePrompt=true / decisions=[]`；应用 926（921 通过、5 跳过、0 失败），类型检查与构建通过。提交 `ee805ab`。
