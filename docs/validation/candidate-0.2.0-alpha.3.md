## 真实窗口验证

### 连接与会话

在隔离源码实例 `host-flow-20261025` 中验证（批次 2 提交后）：

- 平台选 Codex，内置连接器已加载，显示 `codex.exe` 路径；
- 新 `codex exec` 会话注册、可列出、可固定；固定结果写入 `host-session-preference.json`；
- 本地角色回复“开心·欢呼”实际播放，桌宠进入 `happy`；
- 离线（把 hook 日志 mtime 调旧）与重新连接都能在设置页显示。

### 语音

在隔离源码实例 `voice-flow-20261025` 中用临时本地服务验证：

- TTS：20 秒 WAV，播放中点“停止试听”，状态变为“已停止试听，可以重新播放”，不是自然播完；
- 密钥草稿：输入假密钥后切到“桌面与交互”再回来，密钥仍保留；关闭窗口出现“有未保存的云端语音 API 密钥”提示；“继续编辑”保留密钥；“保存并关闭”后 `tts-cloud.json` 中为 80 字符密文，原文无明文；
- 录音取消：开始录音后点“取消”，状态“已取消录音”，临时 STT 服务请求数保持 0；
- 识别失败/重试：第一次 `/stt` 返回 HTTP 500，出现“识别没有成功 / 重试 / 放弃”，重试后文本填入输入框；
- 识别中取消：把 `/stt` 延迟 4 秒，识别中取消后等待迟到响应，输入框仍为空，没有回填；
- 设置页背景化修复：语音页切到其他域时内容真正隐藏（此前 `display:flex` 覆盖 `hidden`）。

### 工坊与预设

在隔离源码实例 `workshop-flow-20261025` 和打包候选上验证：

- 新建预设“测试·工坊草稿”，草稿标记、头部“有未保存的草稿”和“未保存”徽标出现；
- 过渡时间 0.6→1.2 秒后撤销回到 0.6，重做回到 1.2；
- 保存后提示“预设已保存到当前实例”，草稿标记消失；
- 关闭设置时保存并关闭会保存工坊草稿；重启后预设仍在，过渡为 1.5 秒；
- 导出只包含 1 个用户预设，文件带 `schemaVersion: 1`、`kind: uta-user-presets`、当前模型键和 `source: user`；内置预设没有被当成用户预设；
- 导入同一文件提示“已导入 1 个用户预设，覆盖 1 个同名或同 ID 预设”；
- 切到 `sample_static` 后没有该预设，导出提示“当前角色还没有用户预设”；切回 Hiyori 后预设仍在；
- 通过运行时端点 `POST /command` 发送 `set_preset`（按 ID 和按名称）均返回 `ok/accepted`；触发内置“开心”后桌宠实际切到开心表情，证明宿主触发路径可用；

### 资源占用

打包候选独立 profile，默认 Hiyori、窗口可见、空闲 60 秒：

- 12 核机器，候选进程树（主进程 + 渲染器 + 网络服务）CPU 合计 17.64 秒 / 60 秒 = 单核 29.4%，整机 2.45%；
- 工作集合计约 402MB（主进程约 196MB、渲染器约 155MB、网络服务约 45MB）。

这是空闲上限的实测值；开启“安静模式”或把帧率档位调到 30 可进一步降低，但本轮没有单独采样。

## 8 小时 / 7 天试用步骤（待执行）

1. 解压候选，使用 `Try-Uta.bat`，不要直接替换日常 exe。
2. 正常使用至少 8 小时，中途保留一次休眠/唤醒；每小时记录一次托盘进程 CPU、工作集和当前模型是否仍在动。
3. 8 小时结束后检查：设置保存、语音试听、工坊撤销/重做、模型切换、宿主连接是否仍正常；退出再启动一次，确认预设和主题保留。
4. 7 天试用期间每天至少启动一次、切换一次模型并保存一个预设；记录任何白屏、卡死、掉帧、重复回复、语音失败和窗口跑出屏幕。
5. 结束时把 `%LOCALAPPDATA%\Uta-Candidates\0.2.0-alpha.3` 保留为证据；回退只需退出候选并启动旧版，不删除数据。

## 回退

1. 右键托盘图标退出候选。
2. 启动保留的旧版 Uta（不要删除 `%LOCALAPPDATA%\Uta-Candidates\0.2.0-alpha.3`）。
3. 若旧版无法启动，保留整个体验数据目录并记录版本号；不要把新数据复制进日常 `uta` 目录覆盖。
