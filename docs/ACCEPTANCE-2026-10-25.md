## 仍需处理的三项问题

### [P2: 旧发送失败回执覆盖用户后来输入的新草稿]

位置：`app/src/renderer/components/DeskpetStage.vue:843-846,868-879,914-926`。

复现：发送 A，HTTP 请求尚未返回；用户重新打开输入框并输入 B；A 随后返回失败。`restoreUnsentDraft(A)` 无条件将输入框改回 A，B 被覆盖。宿主绑定没有变化，因此新加的 `stillCurrent()` 不会阻止它。

独立探针运行真实 `sendText()` 和 `restoreUnsentDraft()`，期望保留 `newer user draft`，实际变为 `first draft`。此处只模拟异步宿主回执，没有向真实宿主发送消息。

建议：回填也要检查输入草稿的版本/所有权；已有新输入时保留它，把 A 保存在可重试的失败消息中。覆盖“失败期间新输入”“两次提交回执乱序”“切宿主后失败”三个行为。

### [P2: 路径发现接受 cmd/bat 但宿主进程无法启动]

位置：`app/src/main/host-paths.ts:128-131,143-151`；`app/src/main/host-bridge.ts:333-345`。

复现：宿主通过 PATH 或 `UTA_CODEX_EXE` 等配置提供 `.cmd` 入口。路径模块成功找到文件，runner 随后使用 `spawn(command, args, { shell: false })`，在 Windows 上返回 `spawn EINVAL`。OpenCode、Claude 和 Codex 的候选路径都包含批处理形式。

独立探针创建无害的本机 `codex.cmd`，生产 `resolveHostPaths()` 选中它，再调用从生产源码提取的真实 `runInvocation()`，结果为 `ok=false` 和 `spawn EINVAL`。没有调用真实 Codex，也没有排入任何用户会话。

建议：路径发现与执行器统一支持的入口类型；优先定位原生可执行文件或相应 JS 入口。若支持批处理，应设计正确的 Windows 参数转义与固定执行方式，不能直接对携带用户文本的命令笼统开启 shell。

### [P2: Runtime 并发同序号事件没有互斥]

位置：`app/src/main/runtime-sessions.ts:40-78,84-106`。

复现：同一 host/session 的两个并发事件均带 `seq=1`，没有 eventId，或带不同 eventId；第一个尚未完成 sink，第二个就进入 reserve。

结果：inFlight 只记录 eventId，lastSeq 要到 commit 才更新；两次 reserve 均返回 `duplicate=false`，允许重复投递。协议确实允许独立提供 seq，不能假设每个事件都有 eventId。原来的“投递失败后能重试”已修好，此项是新预留机制的并发边界。

独立探针两次调用生产 `reserve()`，第二次期望 true，实际为 false。未用真实宿主或真实桌宠事件触发重复动作。

建议：按 host/session 同时预留 eventId 与 seq；成功、失败、取消及过期清理必须成对收尾。覆盖 seq-only、同 seq 不同 eventId、并发失败后的重试。

### 下一阶段更值得做什么

1. 先修复本轮三项问题，补行为回归，统一错误回填与事件所有权。
2. 选一个主要宿主、一种默认模型、一条真实语音路线，验证“解压启动 → 连接宿主 → 发送/接收 → 审批/播报 → 断线失败/重试 → 重启保留”的全过程。
3. 用独立 ZIP 在一台没有开发环境、安装目录不同的 Windows 电脑测试，再交付版本号、来源、日常入口与说明一致的候选包。
4. 降低连接与语音配置门槛，明确各表单保存范围，补键盘/窄窗/无障碍验收；在相关修复范围内收拢分散的异步状态。

短期优先让普通用户连续使用时少遇到丢草稿、误路由和“显示已连接但操作失败”。继续扩充宿主种类或表现引擎会增加验证组合；应在上述主要使用流程稳定后再安排。
