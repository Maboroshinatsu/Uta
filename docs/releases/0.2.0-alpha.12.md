# Uta 0.2.0-alpha.12 体验说明

这一版把桌宠和 agent 平台的关系改成了一对一：**一只桌宠只绑定一个平台**。同时修掉 Codex 专项验收里的三个问题和共享 Codex 配置的跨实例安装锁。

**首次体验请双击 `Try-Uta.bat`。** 它使用独立体验数据，不读取或修改日常 Uta 的数据。直接打开 `Uta.exe` 会使用日常数据，尚未验收前请不要用它替换旧版。

## 一对一的平台绑定

- 首次引导选好平台后，这只桌宠会固定绑定到它。设置里的“连接与会话”不再列出可切换的平台，只显示当前绑定和连接状态。
- 同一个平台的所有会话共用这只桌宠。比如 Codex 里开两个聊天，它们都会驱动同一只 Uta；Codex 和 DeepSeek Harness 之间不会互相影响。
- 想同时接多个平台：解压包里的 `Pets` 文件夹包含每个平台的启动器。每个启动器使用自己的数据目录和独立端点，例如 `%LOCALAPPDATA%\Uta-Pets\codex`、`%LOCALAPPDATA%\Uta-Pets\harness`。可以同时启动多只桌宠。
- 每个平台插件会优先找自己平台的端点文件，不会连到另一只桌宠；桌宠主进程也会拒绝来自其他平台的事件。
- 想换平台：在“设置 → 关于与诊断 → 平台绑定”里解除绑定，桌宠会重启回独立待机；再重新打开首次引导即可绑定另一个平台。也可以用另一个平台的 `Pets` 启动器。
- 旧版升级：第一次启动会把上一版最后选择的平台迁移成唯一绑定。旧版如果同时用过多个平台，其他平台需要从 `Pets` 启动器新建自己的桌宠；原数据不会删除。

## Codex 专项修复

- **拒绝发言工具不再吞掉最终回复**：只有桌宠发言工具在 `PostToolUse` 明确成功后才记为“本轮已发言”。拒绝、工具失败或投递失败仍会显示最终摘要。
- **hooks 信任按完整清单判断**：不再因为任意一个 Uta hook 有 `trusted_hash` 就把整组显示成已信任。检测会显示“未信任”或“只信任了 x/8（缺少哪些事件）”，并提示在 `/hooks` 里完成其余项。
- **跨实例安装锁**：Codex 安装锁改为按规范化后的 `CODEX_HOME` 共享，不再按 Uta 数据目录隔离。一个 Uta 实例超时未确认退出时，其他 Uta 实例也不能再启动第二次写入。解除阻断对应同一份 Codex 配置。
- 新增的端点文件会带 PID；插件读取时会跳过已经退出进程留下的旧端点，避免多桌宠切换时连到死端口。

## 首次打开与升级

- 首次引导仍然是：欢迎 → 连接宿主 → 选择角色 → 语音（可选）→ 开始使用；现在平台步骤会显示“这只桌宠已绑定到 X”，绑定后只显示该平台。
- 语音默认关闭，引导里不会播放任何声音。
- 从 `Pets` 启动器启动的桌宠已经预绑定对应平台，引导里不会再让你选别的平台。

## 自动验证

应用 **906 项（901 通过、5 跳过、0 失败）**，插件 **105/105**，node/web 类型检查和构建通过。新增回归覆盖绑定文件、宿主专属端点、跨平台拒绝、成功/失败发言标记和部分 hooks 信任；真实双实例验收记录见候选验收文档。

## 数据与回退

日常数据仍在 Windows 用户数据目录的 uta 文件夹。候选体验数据在 `%LOCALAPPDATA%\Uta-Candidates\0.2.0-alpha.12`；`Pets` 启动器使用 `%LOCALAPPDATA%\Uta-Pets\<平台>`，和候选/日常数据分开。

结束使用请右键托盘图标选择“退出”。需要退回旧版时，先退出此候选，再启动保留的旧 Uta；不要为了回退删除数据文件。平台绑定文件保存在各自的数据目录里，删除数据目录会连同角色、预设和绑定一起丢失。

## 已知限制

- 本轮没有在你的真实 Codex 配置上点击安装；安装、权限、hooks 信任和 MCP 握手仍需要按报告里的隔离方式继续验收。
- 平台内所有会话共用桌宠是这一版的设计选择。报告里“另一个 Codex 聊天能影响已绑定聊天”的行为，在新模型下会表现为两个聊天共同驱动同一只桌宠；如果要严格隔离到单个聊天，需要另外绑定会话，不在这一版。
- 同一个平台不要同时启动两只桌宠：该平台插件只会连接最后发布端点的那一只。要换角色/配置，先退出再启动。
- 真实 DSH 桌面安装、其他宿主的真实会话、真实麦克风/云端 TTS、8 小时/7 天、多屏 DPI、恢复页标题栏和贴靠图标同步仍未验收。
- 本候选未替换日常 0.1.1/stable，也未配置代码签名。
