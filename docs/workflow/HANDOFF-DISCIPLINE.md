# Uta 交接与提交纪律

适用范围：`D:/Frankenstein/Uta` 的所有开发会话（Codex、Qoder、DSH、Antigravity 及后续接手者）。
本规则是 2026-11-03 全量审查后立的，依据是那次审查里量化到的返工成本；与 `AGENTS.md` 一起执行，用户最新指令优先。

## 1. 为什么要有这份规则（实测数据）

- 近 4 天 259 次提交，其中 **91 次（35%）是纯文档提交**；文档噪音已与代码等量。
- `app/src` 同期从 203,286 行涨到 216,912 行，**没有瘦身**；高频改动集中在最大的几个文件
  （`DeskpetStage.vue` 2385 行改 39 次、`main/index.ts` 3115 行改 25 次、`SettingsPanel.vue` 2575 行改 12 次）。
- 同一行代码在一天内「加 → 删 → 加」：`0bcd088` 加硬归零 → `aa3dee0` 整行删 → `5c38c82` 加回并塞标志。
- `15f568c` 一次提交塞 4 件不相关事项，并顺带把整份交接文档写成 GBK 乱码，毁掉 1538 行历史正文，
  直到 11-03 才发现（`0940e15` 还原）。
- `docs/workflow/HANDOFF.md` 膨胀到 1794 行纯追加日志，其中的 PID 全部失效、42 处指向已弃用的
  `Uta-Workspace/`，新会话无法据此定位现场。

结论：问题不是「改得太多」，而是**改动没有可核对的边界，也没有可信的现场记录**。以下规则针对这两点。

## 2. 提交纪律

- **一轮改动 = 一个提交**，同一提交里带上该轮的文档更新。不再产生独立的 `docs:` 伴随提交。
  反例：`8f01d50` + `34164c5`、`1b0611c` + `7f11fc5`、`af9b535` + `4148dc7` 这类成对提交。
- **一个提交只做一件事**。提交信息里出现两个以上 `[XXX: ...]` 代号即视为违规，必须拆分。
  反例：`aa3dee0`（4 件事）、`15f568c`（4 件事）、`7d1f18a`（5 件事）。
- **代号必须带全称**（沿用上级 `AGENTS.md` 第 5 条），且提交信息要写清「为什么」，不只是「改了什么」。
- 改动跨越两个以上子系统（如动画 + 待办）时，拆成多个提交，每个提交在自己的子系统内自洽可回滚。

## 3. 返工纪律

- 修同一处行为**第二次失败就停手**：先回答「所有权在哪、为什么上次没修住」，再改代码。
  判据：若一次修复引入了新分支、新标志位或新定时器去抵消上一次的副作用，属于补偿性补丁，不算修复。
- 禁止用「整体还原到某个旧版本」代替定位根因。`ad700c3`（+1039/−625 还原原版 UI）之后 42 分钟
  又被 `e83cd6c` 重新重构，属明确反例。
- 被用户否定的实验变体必须**整条删掉**，不以「保留作对照」为由留在生产运行时里注册。
- 删除功能要删到底：入口、逻辑、IPC/preload、类型、文案、测试、文档一次清完；
  只删模板留脚本孤儿（`SettingsPanel.vue:399-798`）或留死模块配活测试（`daily-todo-send.ts`）都不算删除。

## 4. 交接文档写法

- `docs/workflow/HANDOFF.md` 只有一节「当前现场」，**原地覆盖，不追加**。历史进 `archive/`。
- 现场必须包含：base SHA、分支与工作区状态、本轮改动、已验证与**未验证**清单、下一步止损顺序。
- **禁止把 PID、临时端口、一次性 profile 名字写成「现场」**，改写成重新探测的命令。
  反例：`20152/20240/31004/10392` 这些写下即失效的记录。
- 禁止把未验证写成已验证；数字（测试数、类型检查结果）必须是本次实测。
- **不得向 `D:/Frankenstein/Uta-Workspace/` 写任何新证据、任务或包**（2026-10-24 已弃用）。
  临时验证产物放仓库外的一次性目录，用完删除；正式文档只引用仓库内路径。
- 工作区根 `d:/Frankenstein/HANDOFF.md` 只是指针，不写项目内容；Uta 交接真相在
  `Uta/docs/workflow/`（根目录不受 git 管辖，写进去的内容没有版本保护）。

## 5. 文档编码（硬要求）

- 所有文档一律 **UTF-8**，**禁止在 PowerShell/CMD 里用重定向写中文文件**（默认 GBK 输出会造成不可逆乱码）。
- 写中文文档统一用编辑器/工具的 UTF-8 写入路径，或 `python -c` 显式 `encoding='utf-8'`。
- 提交前由 `app/tests/docs-discipline.test.cjs` 守卫：乱码字符、行数上限、弃用路径引用。

## 6. 验证纪律

- 测试执行入口必须是**目录自动发现**，不接受手工枚举文件清单。
  反例：`session-label.test.cjs` 自 10-31 写下就一直没被执行过。
- 新增回归测试优先断言**行为与终态**（序列结束后的参数值、定时器实际延时、状态机状态），
  不接受只断言「某函数被调用过」或对源码文本做正则匹配。
- 涉及画面观感的改动，验收标准是真实实例里的可见结果；测试通过不能替代观感确认。
