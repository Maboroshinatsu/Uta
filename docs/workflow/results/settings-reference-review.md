执行方意见经过以下修正后才用于方案：

- 原报告写“SPT 33 份全库/未读其余 28”没有充分目录证据。本轮只登记实际读过的五份资料，不替资料库下总量结论。
- 原报告若干拟建路径重复 `renderer/src`。本项目真实源码根为 `app/src/renderer`；未来文件路径要在任务单锁定，不照搬示例路径。
- 仅凭 `minimize` 事件无法证明来自用户操作，仍需区分命令来源与系统事件。普通宿主活动不需要每次闪任务栏；提醒仅用于必要待处理事项且有停止条件。
- 审批时 `showInactive` 仍可能把已最小化的桌宠弹回桌面，不作为默认；不新增系统通知权限，先保留审批与任务栏/托盘可恢复入口。焦点可能导致误操作是待测风险，不写成已复现缺陷。
- 原报告的“隐藏后任务栏一定消失”等表述需按实际 Windows/Electron 行为验证；任务栏分组不承诺固定图标排列。隐藏/最小化均不能销毁桌宠运行时。
- 样式 token 与本地代表页可以先做；真实多窗口/领域数据绑定依赖统一持久化和 IPC 契约，不能倒置为先复制一套 store 再迁数据。
- “配置/取消/审批返回 unavailable”等需要真实接口确认；不因设计文案就宣称底层已经支持。本轮也未安装 Superpowers/UI UX Pro Max/Impeccable 等外部技能。
