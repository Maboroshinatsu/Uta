# Live2D 资源识别链路修复

基线 `main@040be7c`。目标是修复通用资源识别、控件生成、滑块筛选及原生动作身份传递，不新增冰糖或艾莲专用规则。既有 README 改动保留，不纳入提交；不修改用户模型、预设或发行包。

## 原因与修复

- 自动表情控件在候选阶段就登记参数已占用，随后又因参数已占用而跳过自身，导致冰糖与艾莲出现零控件。改为真实发出控件后登记，按完整参数目标/部件操作去重；保留共享通道的不同取值、组合操作及同名独立资源。
- 表情转换统一处理 Add / Multiply / Overwrite、参数范围和未知 ID；无操作的条目不抢占滑块。混合水印与脸部功能逐参数拆分，不再整份丢弃脸红资源；去水印底层不由混合表情中的重置项抢先决定。
- 当前清单声明的 CDI、物理、姿态优先；声明资源支持较深目录。表情文件保留相对路径与注册别名，歧义短名称不随机命中，VTS 热键路径统一斜杠和大小写。
- 已确认的 focus、标准和 VTS 输入优先于弱名称筛选。修复身体输入因“物理”分组被隐藏、标准前缀配件开关被误删、署名被当作滑块名称；实际物理输出、底层和控件已管理通道继续过滤。
- 原生动作的空组名在步骤解析、预览、播放、编辑、存储与导出依赖检查中完整保留。动作库使用文件标签，场景动作标注而不隐藏；长动作出现在能力清单中，临时编排超过 12 秒明确拒绝，不伪装资源不存在。
- 实测关控件发现默认值读取只依赖可选 ById 包装接口，实际 SDK 缺失该接口时误归零。补真实默认值数组和 SDK 索引路径，覆盖非零/负默认值与立即/渐变恢复及后续 savedParameters。

## 验证

完整应用测试 1444 通过、6 跳过，Node/Web 类型检查通过，使用全新绝对输出目录的隔离构建通过。本轮中间两次回归曾出现未修改的 MaiBot 媒体超限请求测试 `ECONNRESET`；最后完整复跑通过，未放宽断言或修改媒体管线。本机受控证据位于忽略目录 `app/node_modules/.cache/model-discovery-evidence/`；探针和汇总脚本在同级缓存目录，不提交模型资产、画面或个人配置。

五个模型分别复制到独立隐藏 profile，使用正常 Cubism 播放器、参数层和物理。读取真实 Core 参数与部件，逐项开启/关闭控件，核对物理前参数及部件透明度；查看开启及恢复截图。表中为当前资源副本的识别数量，不是视觉完成度。

最终绝对路径构建共完成 87 项控件开启/恢复试验，非物理输出的可写目标与回归默认值均通过；Hiyori 的部件开关透明度从 A=1/B=0 切到 A=0/B=1 后恢复。此前相对构建路径导致探针加载旧 renderer 的中间读数不计作最终验收，已重新运行全部模型。

## 边界

- 识别资源不等于自动理解所有编号参数、部件语义或审美表现；没有证据的分层容器不变成独立开关。确认的物理输出不作为主动滑块。
- 同一操作的重复表情允许合并控件；SDK 注册资源清单仍保留。目录兜底扫描深度仍有限，深层资源应由模型清单声明。
- 原生长片段使用与临时 MCP 编排时长限制分开；未扩展 12 秒临时编排上限。
- 未打包、未更新全局插件。尝试沿用授权重载开发窗口时，指定开发端点不可达，未回退其他实例；当前未完成重载。下次启动开发版会加载新的主进程扫描和 renderer。隔离新进程已覆盖两者。
