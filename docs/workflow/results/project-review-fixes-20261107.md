# 项目审查修复

基线 `main@2a56c8f`。本轮按用户要求修复项目审查中的问题，并处理 Hiyori 编排与自动待机的冲突。

## 已验证的修复

- 宿主客户端保留自己的 `UTA_HOST`，逐次传入 `env` 仍使用对应宿主专属端点。发言标记改为宿主加会话隔离，并清理过期文件。DSH 的异步投递测试等待收到目标事件。
- MaiBot 入站保存已鉴权的端点，回复分段、图片、完成状态和角色工具使用同一目标。新版端点携带数据目录的不可逆标识，私聊身份可跨重启延续，原消息引用固定到原请求实例。旧版端点缺少标识时按实例隔离。
- MaiBot/AstrBot 传输中断返回未知回执，前端保留消息记录，避免恢复草稿诱发重发。发送请求使用 UUID。独立 AstrBot 插件 2.0.1 按配对身份和请求编号去重，7 项测试通过。
- 本地 STT 拒绝重定向。回环服务返回 307 时，测试音频不会发往重定向目标。
- 模型首次安装失败后清理本次事务记录，允许原地重试。同目录候选不再共用生成的适配文件，安装目录区分清单名。新预设导出与编排草稿携带资源签名；旧文件要求完整模型路径相符。
- Hiyori 冲突来自 Cubism 在 Uta 停止旧动作后自行重启 Idle。编排播放期间拦住 SDK 自动待机，并让 Uta 的空闲调度让路。编排明确指定的原生动作仍可播放。参数预设 hold 收尾后由控件/滑块层保留终态并释放自动待机，持续循环的编排保持独占。
- 隐藏 Electron 对照实测旧版编排中启动 Idle，新版编排中没有 Idle，结束后恢复。显式 Idle 原生动作可播放、停止。该实验用受控时间线，未评价用户 Gemini 整套成品的美感。
- 在隐藏实例中从 `compile_preset` 生成并导入循环 neutral，连续播放后插入短动作，验证自动恢复 neutral 循环且没有 Idle 插入。
- 用户反馈待机消失后，复制开发 profile 的实际 Gemini 预设到隔离实例复现：四步 `finishMode: hold` 结束后动作独占仍为真。修复后编排中无 Idle，结束后自动启动 Idle，微笑参数保留 0.15；抓取 16 帧确认姿态推进。实际开心预设结束后恢复日常和 Idle，显式 loop 连播保持独占。未修改用户预设数据。
- 候选打包的全新配置验收发现磁盘预设读取丢失 `source: user`、分镜动作引用与零毫秒收尾。主进程及 renderer 声明已补齐；真实隐藏实例验证新版 Hiyori 八槽位保留、FlickUp 播放及完成后恢复 Idle。现有用户配置不强制替换。
- Antigravity 插件诊断分别显示宿主工作区和全局版本，路径来自当前固定会话或最近活跃会话。固定目标失效时保留失效状态。一键安装只更新全局副本，独立测试证明工作区副本保持原版本。
- 全屏期间延后标记日常提醒，退出全屏后立即重新检查。卡片和提示音在实际投递时启动，避免隐藏时消耗展示时间。
- README 调整为用户首次启动、宿主能力与限制、伴侣接入、模型和开发入口。同步快捷切宿主、待办页和动作编排流程，随包 DSH 指引改为支持一键安装。
- 普通包和分享包使用独立名称与说明。普通 ZIP 实查没有分享说明或 DS 资产，隐藏启动 `Uta.exe` 后可加载 Hiyori。分享配置使用人工模型夹具验证额外资源和文档，生成后普通 ZIP 哈希不变。这是临时构建的包内容检查，未进行正式发布。
- 候选启动器用实际批处理加隐藏测试程序验证带空格目录、目录间 profile 隔离、清除继承的宿主和旧端点配置。
