# Uta 用户体验实测评估（2026-11-02）

## 结论

常用功能已经形成可用的桌面体验：角色常驻、快捷设置、日常待办、宿主状态、消息回看与宿主热切换都有实际可见的反馈。熟悉 AI 宿主工具的人较容易开始使用；第一次接触这类产品的人，仍会在连接准备、异常提示和动作编辑中遇到理解成本。

本轮最值得优先处理的是“失败后给用户错误方向”，其次是减少初次配置与动作编辑的操作负担。单元测试通过不等于这两类问题不存在。

## 已确认问题与用户影响

### [P1: Claude 一键安装在失败和超时后仍报告成功]

**证据类型：真实业务模块 + 隔离命令替身复现；没有执行真实安装。**

`app/src/main/host-onboarding.ts:1697` 连续等待两条安装命令，但没有检查返回的 `code`、`stillRunning` 或安装后状态，随后直接返回 `ok: true`，把插件和工具阶段标为 verified。

分别让命令执行器返回以下结果，两轮都复现成功误报：

```js
{ code: 1, stdout: '', stderr: 'installation failed', stillRunning: false }
{ code: -1, stdout: '', stderr: 'command timed out', stillRunning: true }
```

第一条命令失败/超时后，第二条命令仍继续被调用，最终显示“已成功通过 Claude CLI 安装插件”。默认执行器以返回结果表达失败，并不保证抛异常，因此外围 catch 捕获不到这些正常返回的失败。

**用户影响：**用户会以为已经安装好，转而反复重启和检查会话；界面把真实失败原因隐藏了。

**建议：**逐条判断退出状态；失败即停止后续步骤；对超时且未确认退出的写入保留阻断；安装后独立核验，再显示成功。补上非零退出和超时回归用例。

本机复现脚本：`app/node_modules/.cache/ux-review-20261102/reproduce-install.cjs`；同目录 `install-failure-results.json` 保留结果。脚本只操作自身临时目录。

### [P2: 未绑定宿主时输入框持续建议退出重启]

**证据类型：第一轮生产入口的原生窗口实测，并核对源码。**

复现：全新独立 profile → 引导跳过宿主 → 完成引导 → 双击角色 → 输入框持续显示：

> 正在确认发送通道；若一直不可用，请完全退出后重新启动 Uta。

等待后没有变成“请先绑定宿主”。同时，连接页明确知道当前为独立待机。`DeskpetStage.vue:463` 在输入状态为空时使用上述通用回退文案。

**用户影响：**用户把缺少必要配置误认为程序卡住；照着提示重启不能完成绑定。

**建议：**优先判断未绑定状态，显示“请先在快捷设置选择宿主”，提供可点击入口；只有实际查询中的状态才显示等待，查询失败另给重试。

### [P2: 新手引导中的角色展示与完整设置不一致]

完整设置显示友好名称 `Hiyori Pro`、`示例立绘·团子`；引导里显示 `hiyori_pro_zh / hiyori_pro_t11`、`sample_static`。没有缩略图或页内预览，用户只能看桌面上的即时切换效果。

**建议：**引导复用友好名称，显示缩略图、展示类型与当前角色，保留明确的默认推荐。

### [P2: 工坊高频操作分散在过长页面中]

进入预设工坊后，首先仍是角色管理、模型校准、导入导出和完整原生动作库；继续滚动才到自然语言描述、分镜、时间线与参数。生成六步后，分镜列表再次变长，保存与预览操作不在当前可见范围。

**用户影响：**普通用户要先理解预设/动作/常驻/分镜的区别，且编辑时需反复滚动寻找操作和反馈。功能可用，但尚未形成轻松的“做一个动作”流程。

**建议：**常用动作与高级编辑分别设置明确入口；编辑时固定预览、撤销、保存操作；原生动作库默认收起或按需选择；保存结果和当前草稿名称保持可见。

### [P3: 接入能力介绍和部分说明仍有旧文案]

- 引导正文仍只强调 Codex/DSH 可直接安装；新卡片已提供更多宿主的一键安装。
- Qoder 卡片仍说“本版不自动改写 Qoder 配置”，展开后却是支持自动安装的流程。
- 宿主差异尚未在选择时足够明确。例如 Qoder 卡片没有直接提示桌宠内双向文字输入的限制；README 中的能力表不能替代用户正在操作的界面提示。
- “桌面与交互”找回窗口说明出现“设置中心不另做假开关”“由主进程托盘提供”等实现导向表述。

**建议：**按用户能否接收状态、是否能在桌宠里聊天、安装完成后需要做什么组织卡片；清理与实现状态不一致或不帮助用户操作的表述。

## 对当前体验的判断

- **日常陪伴：较好。**小状态胶囊、短气泡、消息回看、快捷开关和待办能形成持续使用的理由。本轮没有长时间常驻证据，不能据此判断整日资源占用和可靠性。
- **常用设置：较好。**导航、明暗主题、自动保存和跨入口一致性都有正向体验。
- **初次接入：尚可，恢复引导不足。**可跳过配置是优点，但错误状态与下一步动作还没有全部对齐，安装成功误报必须先修。
- **角色与动作定制：能力多、学习成本较高。**自然语言灵感有帮助；界面仍偏向理解模型参数与预设编排的用户。
- **声音与真实宿主收发：暂不评分。**本轮没有真实账号发送、真实语音服务和最终打包版证据。

优先顺序建议：先修安装结果与未绑定提示，再统一宿主能力说明、角色缩略图和工坊操作布局；不必先继续增加更多设置项。
