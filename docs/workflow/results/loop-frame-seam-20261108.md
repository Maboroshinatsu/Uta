# 循环末帧直接衔接首帧

基线 `main@1d0a298`。用户明确要求：播完下一帧直接从头播放，不额外插入回程、待机或重新交接视线。本轮只修改循环时间线、原生循环淡入和相应参数落地及导出；保留 README 既有改动，不改用户模型、预设、插件或发行包。

## 行为

- 参数序列首次进入保留首步过渡；循环重启直接应用首帧，跳过首步入场过渡及同长等待，只保留作者明确设置的首帧保持时间。后续步骤时长不变，沿用序列令牌与所有权，不反复归还视线或回待机。
- 原生循环关闭 Cubism 的逐轮淡入，新加载与缓存动作都处理；保留首次正常淡入。单步绑定原生动作也交给 SDK 持续循环，不通过反复重新启动模拟。
- 实测发现零时长直接写头身偏移会被 SDK 帧开始的 saveParameters 收进底层，再叠加一遍。改为零时长叠加通道在下一帧参数阶段应用，常驻底层和绝对值仍即时同步。回归覆盖标准/自定义身体、眼睑和待机眼球，连续切换不翻倍、不污染 savedParameters。
- 多步循环导出从首个作者姿态开始，首步入场过渡不烘焙进循环文件；显式首帧保持和后续运动保留。

## 证据

- 旧代码的控制器测试复现每轮多出 200ms 首步过渡，原生逐轮淡入默认开启。修复后的首次入场、无保持/有保持接缝、单步原生循环、停止与视线所有权回归通过。
- 新旧隔离构建均使用绝对路径；Hiyori 副本真实渲染对照中，旧版没有直接首尾跳转；新版在相邻渲染采样约 33ms 内从约 +8 回到约 -8，连续多轮没有 -16 翻倍或累积漂移。仍保留正常物理与参数层，不强写渲染输出。
- 合成原生 clip 只加入实验模型副本，经正常预设入口验证整段与单步绑定循环，检查 SDK 循环、逐轮淡入和切换静态预设后的所有权及旧动作停止。
- 大肥鱼、冰糖、艾莲去适配器、匿名模型名副本再次通过自动身体跟随：左右、循环、表演打断恢复、关闭/开启。此项在单步原生补充前的同轮构建验证，后续只新增单步原生路径，未改此多步参数路径。
- 完整应用测试、类型检查与构建结果见 HANDOFF。忽略目录 `app/node_modules/.cache/loop-seam-evidence/` 保存渲染帧与读数；同级探针、测试/构建日志不提交。动态对照是实际录帧的并排播放，不是参数插值生成的图像。

## 边界与现场

- 直接衔接不自动修正动作首尾姿态；首尾不一致会跳变，播放器不再额外补一段回程。循环没有自动反向播放。单步纯静态姿态仍保持终态。
- 单次设置不能保证任意第三方 rig 的自然程度，用户实际模型和真实鼠标的主观体验仍待确认。未打包。
- 本轮一次失败探针退出后，临时副本目录清理失败；后续显式清理被自动审批以“blocked by policy”拒绝，未绕过，目录保留。其余成功探针清理自身 profile；无本任务遗留测试进程。
