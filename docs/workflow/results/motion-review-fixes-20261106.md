# 动作编排审查修复与随包资源

- 宿主编排把临时控件叠加到模型渲染层，用户衣装档位保存在原状态。普通一次性预设沿用控件状态行为，用户原先开启的多档位控件通过临时层改档。回归覆盖正常结束与中断后恢复档位。
- 原生动作先返回 `starting`，实际启动后进入 `playing`。时间线结束与原生完成都到达后才返回 `completed`。隔离实窗通过 MCP 复现了缺少动作文件的路径，修复后终态为 `failed`。大肥鱼「竖手指打开」和临时眼镜组合的完成、停止与清理均通过。
- 默认编排槽位独立读取模型模板与初始种子。用户连续导入两份同 ID 草稿后，模板槽位仍可编译。原生时长按清单的组与索引读取，缺少清单元数据时按模型内相对路径查找。回归验证不同目录的同名动作保留各自时长。
- 仅从 VTS 导入生成的身体映射要通过可写输入过滤。显式适配保留原有优先级。
- Antigravity 和 Qoder 的随包资源同时声明解包目录和 ZIP，设置中的一键安装可使用解包目录。安装回归读取真实构建配置生成隔离资源路径。本轮未生成新发行包。

## 2026-11-08：待机循环与视线跟随

- 原因：多步循环沿用一次性预设的末步视线交接，末步打开跟随、下一轮又压低权重；眼球关键帧还会绝对覆盖鼠标输出。
- 约定：`neutral` 或「日常待机 / 日常」分组的 `loop` 预设是环境动作，头身与眼球偏移叠加鼠标跟随。其他多步表演循环整段控制视线，循环接缝不交接；一次性演出的收尾行为保留。未改预设数据或 skill。
- 眼球叠加发生在正常参数栈内，物理后不重复绝对覆盖；首次过渡从默认偏移起步，切换绝对/叠加坐标时换算当前值，释放时淡出偏移，避免双倍跟随或污染 SDK 保存基线。
- 行为回归覆盖多轮接缝、表演打断与回退、眼球叠加/释放及有无 natural-movement 钩子的两条渲染路径。完整应用测试 1408 通过、6 跳过，Node/Web 类型检查及隔离构建通过。
- 正常播放器隔离验收：复制 Hiyori 和大肥鱼到一次性 profile，使用私有端点播放相同双步待机/表演。只固定输入端的鼠标目标，保留预设播放器、物理与实际渲染；Hiyori 旧版对照眼球停在预设 ±0.08，修复后两模型均能维持右侧约 0.47～0.63、左侧约 -0.63～-0.47，跨多轮接缝及插入表演后回退通过。已看真实截图，测试实例均退出、临时 profile 清理。
- 本地日志和预览位于忽略目录 `app/node_modules/.cache/idle-gaze-evidence/`，探针为同级 `idle-gaze-probe.cjs`；它们是受控输入验收，不代表用户当前运行实例的鼠标端到端验收。未重启用户实例，未生成新发行包。
