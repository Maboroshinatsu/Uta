更新于 2026-11-06。上一轮见 [MaiBot 鉴权归档](archive/HANDOFF-maibot-auth-20261106.md)。

## 1. 仓库与版本

- 分支 `main`，本轮基线 `feb5e04`，开工时工作区干净。用 `git status --short --branch` 和 `git log -4 --oneline` 核对。
- MaiBot 适配器 0.3.0 回推私聊图片和表情包。Uta 通过独立鉴权路由接收，沿用气泡准入策略和历史文件版本。恢复历史媒体时只显示在记录面板。

## 2. 运行现场

- 用 `Get-CimInstance Win32_Process` 核对开发实例，用 `Get-NetTCPConnection -LocalPort 8524 -State Listen` 核对 MaiBot 监听。验证使用隔离端口和模拟消息网关。现有开发实例及日常配置未操作。

## 3. 验证状态

- 隔离回环测试覆盖媒体转发、混合和纯媒体回复、鉴权、超限、去重和历史恢复。适配器 20 项测试通过，应用测试 1376 通过、6 跳过，Node 与 Web 类型检查及隔离构建通过。

## 4. 已知未修问题

- 本机部分旧 Codex 聊天的名称只在 SQLite 状态库。Uta 不从 SQLite 补拉缺失的标题。Qoder 等未提供实际标题的连接器仍可能显示未获取标题。
- Codex 连接器共用客户端的逐次 `env` 会覆盖握手默认的 `UTA_HOST`。仅发布宿主共享端点时，握手可达，工作和完成事件可能找不到桌宠。
- Uta 气泡缺少附件发送入口。MaiBot 工具、跨设备连接及旧版数据导入仍待实施。截图和摄像头不在当前批次。

## 6. 下一步建议

- 实机复验时同步更新 Uta 和 MaiBot 插件。宿主固定与自动选择策略待确认。
