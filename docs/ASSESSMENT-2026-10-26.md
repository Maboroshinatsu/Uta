## 当前新确认问题

### [P2: 即时保存的单字段失败被其他字段成功掩盖，关窗丢失未落盘设置]

位置：`app/src/renderer/settings-window/use-settings-draft.ts:82–94,124–144,199–200`；关闭判断 `use-settings-close.ts:33–42`。

触发顺序：

1. 将主题从浅色改为深色；模拟这次持久化失败。界面保留深色草稿并显示失败，安排重试。
2. 在重试前关闭“视线跟随”；第二个字段成功写入。
3. 第二次成功把全局 `saveStatus` 改为 `success` 并清空错误，但主题仍是未落盘的本地值。
4. 原主题的重试只在 `saveStatus === 'error'` 时运行，因此被跳过。`hasPending()` 也不包含尚未写成功的字段。
5. 正式关闭守卫只检查全局 error/当前队列和其他草稿，于是直接批准关闭。重开后主题回到浅色。

本轮探针执行生产 `useSettingsDraft()`、`useSettingsClose()`，只替换持久化响应与计时器，结果如下：

| 观测值 | 结果 |
| --- | --- |
| 第一次保存失败后的状态 | `error` |
| 第二字段成功后的状态 | `success`，错误为空 |
| 本地主题 / 已提交主题 | `dark / light` |
| 是否声明有待写入内容 | `false` |
| 执行重试计时器后的累计写入数 | 2，没有重试主题 |
| 关窗提示 / 主进程回执 | 未提示，发送 `close` |

这是当前的保存状态与关闭保护缺口，不是整份设置损坏，也不代表正常即时保存全部不可用。已有 919 项通过未覆盖“字段 A 失败 → 字段 B 成功 → A 重试 → 关窗”的组合。

建议：持有逐字段的未提交/失败集合；成功只清理此次已确认的字段，保存状态由全部待写字段推导；重试与关窗读取该集合，不能只依赖最后一次操作的全局状态。本轮未实施修复。

本机复现：`.tmp/assessment-20261026/autosave-probe.cjs`；结果：`autosave-probe.json`。该结果是生产 composable 的受控持久化故障注入，不声称已在真实用户目录制造磁盘失败。

### 修复（2026-10-26 追加）

已修复，提交 `ee805ab`。`use-settings-draft` 现在维护逐字段 `failedKeys` 未落盘集合：一次写入成功只清理本次成功的字段，全局状态由全部失败/未落盘字段推导；重试计时器不再依赖“最后一次操作”的全局 error，只要集合非空就重试；`hasPending()` 同时检查失败集合与 draft/baseline 差异。关闭守卫在任一字段仍失败时提示；没有工坊/密钥草稿时主按钮为“重试并关闭”，重试成功后才批准关闭。

回归：`settings-window-draft.test.cjs` 新增“后一字段成功不掩盖前一字段失败”和“关闭重试失败字段”两条真实 SFC 测试；将本评估探针断言反转为修复后预期后运行，结果为 `status=error / pending=true / 重试再次写入 themeMode / closePrompt=true / decisions=[]`。应用 **926 项（921 通过、5 跳过、0 失败）**，类型检查与构建通过。
