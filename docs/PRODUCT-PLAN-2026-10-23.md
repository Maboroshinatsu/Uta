## 1. 产品要成为怎样的东西

Uta 是常驻桌面的角色伴侣：能理解正在协作的平台状态，以自然、有节制的表情和动作回应，同时给用户清晰可控的设置与创作工具。MaiBot、Codex 等是连接对象；Live2D 是角色表现载体；它们都不应决定整个设置界面的组织方式。

这轮产品化的三个结果：

1. **角色有持续的状态和动作衔接。** 收到事件后不只是切一个预设；等待、思考、说话、成功、失败、恢复日常之间能自然过渡。现有预设仍可用。
2. **设置变成真正的桌面设置中心。** 保留蓝色大色块的角色气质，任务归类清楚；桌宠和设置独立操作，日常使用不被编辑工具打扰。
3. **开发不依赖主控始终在线。** Codex 提前准备有限、可检查的任务包；Qoder、Antigravity 能独立提交成果，主控回来后集中审查、集成与发版。

优先级：Live2D 的能力识别、控制协调和可重复验收先于大量新动画；统一设置来源先于多窗口真实绑定；契约先于并行实现。不能先把六页都画完，再补状态同步。

## 2. 用户旅程与产品验收

| 旅程 | 预期体验 | 失败/缺失能力时 | 完成证据 |
| --- | --- | --- | --- |
| 首次使用 | 解压 ZIP → Uta.exe → 看到角色 → 知道当前是否连接 | 没有后端也可查看角色和设置，不死等连接 | 干净测试 profile 的解压版录屏/日志 |
| 换角色 | 选择模型，看到可用动作与表现能力；保留旧角色直到新模型可用 | 加载失败保留原角色；缺眉毛/元音等能力明确降级 | 换模失败、快速连续换模、重新启动 |
| 连接平台 | 选平台和会话，看到发现工具、握手、绑定、画面执行的分别状态 | 地址错误保留草稿，可局部重试；不自动连日常实例 | 指定会话真实端到端证据 |
| 日常协作 | 低干扰待机 → 收到任务 → 思考 → 回复 → 完成后恢复 | 音频失败不假装已经播出；旧会话不能继续操纵新角色 | 相同事件脚本 A/B，对应 request/session/model 关联 |
| 最小化 | 桌宠最小化后可从任务栏恢复；设置继续操作 | 普通事件不自动恢复桌宠；审批仍待处理并提醒 | Windows 真实双窗口操作 |
| 配语音 | 分清服务配置、试听、实际播报，保存结果明确 | 试听失败保留输入；识别测试不自动发给 Agent | 有声试听、静音、断网、取消、切服务 |
| 改动作 | 工坊预览、撤销、恢复、保存相互明确 | 关闭/崩溃释放预览控制权，不污染日常姿态 | 预览与外部事件冲突/退出后的画面 |
| 排查问题 | 看得出启动的是哪份程序、哪个 profile、哪条连接 | 数据/密钥脱敏，局部失败可定位 | 用户诊断摘要与开发细节分层 |

## 3. 产品范围与边界

本阶段包含：Live2D 表现运行时升级；蓝色设置中心；角色能力校准与表现预览；统一持久设置；双窗口生命周期；有限任务队列；真实 ZIP 验收。

暂不纳入首轮：换渲染框架、全量升级 PIXI/Cubism、3D/VRM、摄像头面捕、自动训练动作模型、全天主动 LLM 对话、任意参数远程控制、市场/账号/云同步。后续可在边界稳定后独立评估。

不把“每秒动作更多”当表现力。默认自然、克制；允许安静模式和强度调节。错误和审批用清楚状态表达，不用角色表演代替真实结果。

## 4. 设置与视觉方向

沿用已经确认的信息架构：角色与动作、连接与会话、语音、桌面与交互、外观与性能、关于与诊断。工坊进入设置中心内的专用工作区，默认仍只有桌宠和设置两个系统窗口。

视觉改为**蓝色大色块 + 清楚的文本层级 + 宽松的表单**。图标里的浅蓝用于品牌大区域，深蓝用于重要按钮与可读文字，灰蓝用于次级区域；不把所有表单都涂蓝，不用一堆小彩色卡片代替信息结构。具体色值、布局和状态见视觉规范。

“角色与动作”增加面向普通用户的“表现”区域：自然程度、表现强度、注视与互动、说话动作、恢复默认。详细参数映射、曲线和控制来源放工坊/高级校准，不让普通用户先学 FACS、VAD 或 Cubism 参数。

保存规则：安全可逆的偏好即时保存；连接配置与工坊有明确草稿；试听/播放/预览不保存；跨窗口读取主进程发布的带 revision 快照。外部事件不覆盖正在编辑的草稿。

## 5. Live2D 目标与取舍

选择渐进替换：保留 Uta 的加载、模型发现、预设、原生动作和音频链路，在它们与最终模型写入之间引入可观测的表现编排与通道控制。新系统先在开发 profile 下对照旧系统，再按模型启用。

- 情绪连续变化，不让每次重复事件都强制重启同一动作。
- 各层有明确的控制通道、生命周期、释放方式和限制；工坊、口型、表情、原生动作、呼吸、注视不再靠分散写入“谁最后写谁赢”。
- 尊重模型的真实参数和原生资源；自动识别只提出建议，不能保证识别出所有私有参数的含义。
- 语音使用实际播放时钟和音频特征；文字驱动只作无音频时的视觉回退。
- 自然动作先做可调的低成本程序生成；AIRI 的 MAGIC 统计动作作为后续实验，不是首版硬依赖。
- Soullink 的纯引擎、Profile 与覆盖率值得先做隔离试验；不直接引入其 PIXI7 渲染器。最终采用依赖包还是参考自研，必须经过适配/大小/性能/许可证核对的选型关口。

详见架构文档中的逐通道规则、迁移和评估，而不是只新增“情绪强度”滑块。

## 6. 开发治理与离线推进

Codex：产品/架构/接口冻结、任务授权、审查、集成、发布。Qoder：数据、纯逻辑、协议/存储、表现内核。Antigravity：设计系统、设置页面、校准与工坊交互；可按任务包承接渲染集成，但同一文件只能有一个 owner。DSH 仅兼容性测试。

Codex 暂不可用时，执行者按已授权队列工作。任务从开始就不要求 Codex 每一步回复；不能把“额度已经耗尽”当作唯一启动信号。真正持续的执行要由本机独立 runner 保存队列、状态和日志，而非等此聊天自动醒来。当前 CLI 派单已验证，**持久调度与无人值守恢复尚未实现**。

不自动购买额度、使用新密钥、更换模型、扩大权限、升级依赖、合入 main 或替用户发布。执行者可以提交任务分支和在预先批准的同 owner 任务栈继续工作；独立审查可辅助发现问题，但不代替 Codex 合并决定。具体上限和失败处理见运行规则。

## 7. 阶段、交付门槛与依赖

以下是依赖顺序，不按日历保证工期。每个关口只接受本阶段证据；源码通过不等于发布通过。

| 阶段与完整名称 | 交付 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| 阶段一：契约与基线 | 设置/窗口/表现/任务接口冻结；旧画面对照脚本；蓝色代表页 | 用户确认此方案 | fixtures、字段语义、文件 owner、验收脚本齐全；不阻塞的任务明确 |
| 阶段二：开发连续性与数据底座 | 本机有限队列、profile 隔离、统一设置读写/迁移 | 契约已冻结 | 假 CLI 故障演练 + 两个真实平台各一次断点续接；设置不串写/可回退 |
| 阶段三：表现基础 | 模型 Profile、参数控制协调、旧预设适配、回放工具 | 表现契约 + 基线 | 无冲突/越界/旧模型残留；旧功能回归；三类模型可降级 |
| 阶段四：日常表现闭环 | 自然待机、情绪过渡、语音节奏、事件编排 | 表现基础合入 | 同脚本 A/B 通过行为与主观验收，音画对齐证据 |
| 阶段五：设置与创作闭环 | 双窗口、六领域、表现校准、工坊草稿与撤销 | 设置底座；窗口/运行时 IPC 已合入 | Windows 操作与跨窗口一致性验证；低分辨率/键盘/长文本通过 |
| 阶段六：兼容与交付 | 各宿主验证、回滚、ZIP 解压 exe 候选 | 前阶段集成通过 | 用户验收新 ZIP 后才提升 stable 登记 |

阶段二/三的纯模块和阶段一 UI 组件样板可以并行；真实设置接线不能绕过阶段二，真实表现校准不能绕过阶段三。可先交付“表现基础候选版”，不必等六页全重写才让用户看角色改善。

## 8. 发布、回退与数据

每个候选记录源码 SHA/dirty、依赖锁、构建命令、ZIP 哈希、隔离数据目录和实际验收结果。默认禁止 dirty 构建冒充可复现版本。正式数据先备份，迁移有 schema/revision 和旧数据留存；模型资源与用户覆盖分开，模型旁车只读作为旧来源。

功能开关按 profile 保存：表现新运行时、模型映射版本、窗口新版。切回旧表现应释放全部新控制层并重新应用旧日常状态，不靠同时运行两套写入器回退。设置迁移使用旧备份恢复策略，不能仅靠隐藏新 UI 撤销已经写入的数据。

日常可用版本仍是独立发布目录的 Uta.exe；本轮文档合并后也不更新其版本。源码开发页面、CLI 报告、演示线框都不是已验收日常版本。

## 9. 风险与实际决定

| 风险 | 决定与应对 |
| --- | --- |
| 一次重写过大、再次形成大文件 | 先契约/行为回放，再按有独立职责的模块替换；不按行数机械拆分 |
| UI 好看但角色没有改善 | 表现基础与 A/B 提前成阶段门槛；设置改造不是唯一路线 |
| 动作彼此覆盖或物理抖动 | 区分物理前输入和物理后最终约束；控制权可追踪，保留原生物理 |
| 自动参数猜错、模型表情怪异 | 置信度 + 用户确认 + 每模型覆盖，低置信度不自动驱动私有参数 |
| 更多特征带来过高占用 | 不逐帧调用 LLM/IPC/响应式全量 store；先测旧版基线再设预算 |
| 两个平台长期失控推进 | 有限任务数/运行时长/重试上限；无人审查时停在 submitted；无默认无限循环 |
| Worker 改坏公共接口 | 只读契约目录；越界结果拒收，不能临时重写另一 Worker 的接口 |
| 只有主控能合并造成停顿 | 提前备足独立任务与受控任务栈；允许可审查产物累积，接受集成点需要主控 |
| 参考项目代码能用但重依赖不合适 | Soullink 纯引擎独立试验；AIRI 借边界/控制策略；不一并迁工具链 |
