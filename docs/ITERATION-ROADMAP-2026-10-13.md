# Uta 后续迭代方案

日期：2026-10-13（Asia/Shanghai）

受众：项目维护者、实现本方案的开发者和后续 Agent

状态：待讨论的实施方案；本轮仅编写文档，不代表已授权开始结构改造

目标：以 Uta 为独立桌宠运行时，支持 DeepSeek Harness 与通用角色工具入口，将 MaiBot 接回为可选后端。

## 1. 产品目标与实施边界

### 1.1 下一阶段要交付什么

用户安装一份 Uta，保留现有 Live2D、静态立绘、预设工坊和桌面窗口能力；选择已支持的宿主并绑定明确会话后，获得该宿主实际支持的状态、公开回复、角色工具和输入能力。

DeepSeek Harness 保留原生插件形态，MaiBot 保留宿主 SDK 插件形态。宿主插件负责接入，不承担模型渲染；Uta 负责角色表现，不承担 agent 推理循环。

首个多宿主版本允许多个接入端存在，但只有一个“当前活动绑定”驱动对话与角色状态。非活动会话不抢占声音、气泡、动作或审批卡片。

### 1.2 本轮不扩大哪些范围

- 不重写 Vue、Pinia、PixiJS、Electron 或现有模型渲染器。
- 不立即拆成多个 Git 仓库或独立发布全部内部模块。
- 不承诺通用 MCP 工具入口能读取宿主会话、持续订阅回复或发送输入。
- 不读取隐藏推理，不靠抓日志、录屏或数据库扫描补齐宿主缺失的接口。
- 不在统一宿主改造阶段同时引入全套云语音提供商。
- 不将另一智能体在 MaiBot Deskpet 中进行的修复重新实现一遍；迁移前核对修复结果和测试。

### 1.3 需要明确的产品决策

以下是实施前需要确认的选择。本文提供推荐值，不把推荐写成既有用户授权。

| 决策 | 推荐 | 影响 |
| --- | --- | --- |
| 独立产品名称与主体 | Uta 为通用桌宠主体，MaiBot 为可选适配器 | 后续通用前端功能在 Uta 开发 |
| 默认接入体验 | 优先完善已有 DeepSeek Harness 链路 | 首次验收有真实状态、回复和角色工具 |
| 会话范围 | 首版一次绑定一个宿主实例中的一个会话 | 控制并发与内容归属复杂度 |
| 桌宠审批 | 保留当前交互卡片作为可关闭能力，所有决定交回宿主验证 | 需要与旧规划“审批只留在宿主”协调 |
| RP 人设 | 保留功能，注入主回复、展示回复、语音播报三个开关独立 | 避免用户只想看状态却被修改主窗口语气 |
| 默认语音 | 关闭，后续按活动绑定显式开启 | 避免双重播报和跨会话声音混杂 |
| 初期分发 | Uta 安装器或便携包 + 单独宿主插件 | 不依赖宿主自动安装 Electron 应用 |

## 2. 已核对的代码现场

本方案基于 2026-10-13 对本地文件的只读检查。Uta 的 app/package.json 为 0.1.0；仓库当时没有首个提交，README、app、docs、plugin 均未跟踪。另一个智能体可能继续修改文件，因此实施时必须重新核对现场。

本次没有重新运行 Uta 测试、生产构建或真实宿主验收。旧文档和 README 的测试数量、真实激活记录属于历史记录，不能当作本轮验证结果。

### 2.2 当前结构缺口

1. **统一适配层未贯穿主链路。** 注册表中的 harness、maibot 仍不可用；实际 Harness 指令经 IPC 直接进入 DeskpetStage.vue 的 applyRuntimeCommand()。HostAdapter 的事件订阅与通用控制器没有成为舞台的实际宿主入口。
2. **连接状态表达不足。** host-status 返回运行时端点、端口和 renderer 就绪状态，不能证明某个宿主插件在线，也不能证明已绑定会话。
3. **会话归属不足。** Harness 插件内部保存 agent/session 相关流状态，但发往桌宠的工作状态没有统一会话信封。多会话会竞争全局角色状态。
4. **流式语义不一致。** 插件 chunk 分支发累计 cleanText，舞台用 appendChatText() 追加；这两端需要统一为增量或快照。
5. **切换与生命周期不足。** active.ts 能替换单例，但舞台 setup 持有旧适配器引用；切换后不能仅假定引用和订阅会自动更新。
6. **语音尚未实现。** 当前 isSpeaking 的文字表现不等于真实 TTS 音频与音频驱动口型；产品说明需要区分。
7. **分发需要独立验收。** 已有 dist 命令，但检查时 app 根目录未发现独立 electron-builder 配置；没有据此断言打包必然失败，需要明确资源布局并实际安装验证。
8. **历史文档有决策差异。** AGENT-PORTABILITY-PLAN.md 规定审批留在宿主，当前 Harness 插件支持桌宠做一次性审批；MIGRATION.md 的“移除口型/尚未真实安装”等历史内容也不能继续代表当前全部状态。

## 3. 目标架构

### 3.1 推荐的数据流

```text
DeepSeek Harness 原生插件 ──本机 HTTP──┐
通用 MCP 角色工具入口 ─────本机 HTTP──┼─▶ 主进程 Host Gateway
MaiBot SDK 插件 ───────────WebSocket──┘      │
                                            │ 认证、协议校验、来源登记
                                            │ 会话绑定、去重、生命周期
                                            ▼
                                   版本化统一宿主事件
                                            │ 固定 IPC
                                            ▼
                                  Renderer HostClient
                                            │
                                            ▼
                                   统一事件控制器
                                            │
                           ┌────────────────┼────────────────┐
                           ▼                ▼                ▼
                      角色状态/模型     气泡与回复         审批视图
                           │                │
                           └───────可选媒体提供方───────────┘
```

Host Gateway、HostClient 是本文建议新增的内部模块名称，不是现有宿主 API。所有新增路由、IPC、事件名称也都是 Uta 内部设计提案，实施时需要契约评审与版本化。

### 3.2 各层责任

| 层 | 责任 | 不应承担 |
| --- | --- | --- |
| 宿主插件 | 宿主事件订阅、公开内容提取、合法输入与审批结果回传 | 渲染、窗口、Uta 本地文件操作 |
| 传输驱动 | HTTP 接收或 WS 连接、超时、重连、认证 | 表情选择、聊天记录修改 |
| 主进程 Host Gateway | 识别接入实例、绑定会话、校验事件、派发反向请求 | 直接写 Pinia 或模型参数 |
| Renderer HostClient | 接收统一事件、提供响应式绑定信息、提交用户请求 | 保存令牌、另建宿主网络连接 |
| 统一事件控制器 | 状态、文本、角色命令分发与恢复规则 | 判断具体宿主类型 |
| 桌宠核心 | 模型、预设、状态、气泡、动作与交互 | MaiBot SDK、Harness 私有载荷 |
| 媒体层 | 转写、合成、播放、取消、音频口型 | 推理、宿主会话管理 |

主进程承担网络连接与令牌管理，避免每个渲染组件各自维护连接。现有 renderer/services/adapters 中的逻辑逐步迁移；过渡期间保留薄兼容包装，完成后删除双入口。

### 3.3 建议目录

下列是目标布局，阶段实施时逐步创建，不要求一次性搬动全部文件。

```text
Uta/
├── app/
│   ├── src/shared/host/          事件、能力、请求结果、校验规则
│   ├── src/main/host/            Gateway、实例登记、绑定、连接驱动
│   │   └── drivers/              runtime-push、maibot-ws
│   ├── src/preload/              最小固定 IPC
│   └── src/renderer/services/
│       ├── host/                HostClient、统一控制器
│       ├── live2d/              现有角色能力
│       ├── imageset/             现有静态立绘
│       └── media/                提供方与播放调度
├── plugin/plugins/
│   ├── deepseek-harness/          现有原生插件，按职责拆模块
│   ├── deskpet-mcp/               通用角色工具入口
│   └── maibot/                    SDK 插件与版本说明，阶段接入时创建
└── docs/                          开发协议、验收、用户安装与交接
```

共享契约可以先放 app/src/shared/host。纯 ESM 的宿主插件使用发布时生成的 JSON Schema/协议版本常量与契约夹具，避免从源码路径临时导入 TypeScript。暂不要求引入 monorepo 工具或新依赖。

## 4. 实施前要固定的协议

### 4.1 统一事件信封

拟定字段如下；字段限制、IPC 类型与 HTTP 校验须使用同一份定义。

| 字段 | 用途 |
| --- | --- |
| protocolVersion | 事件协议版本；与 runtime-endpoint.json 的发现文件版本分开 |
| eventId | 重试去重标识 |
| hostId | 宿主种类，例如 deepseek-harness、maibot、mcp-tools |
| instanceId | 同类宿主的具体进程/接入实例 |
| sessionId | 内容与任务所属会话；纯角色工具可没有会话 |
| turnId | 当前轮次；不可证明关联时不能编造 |
| sequence | 同一回复流内单调序号 |
| occurredAt | 展示与诊断时间，不作为唯一排序依据 |
| kind、payload | 明确的事件类型与结构化载荷 |

来源身份由已配对的连接上下文赋予。载荷中的 hostId/instanceId 只是待核验声明，不能仅凭它们授权会话内容或审批。实例登记与令牌策略须说明共享令牌能做什么；会话过滤也不能被描述成认证。

### 4.2 事件与能力

统一事件至少包含：连接/实例状态、会话声明、轮次开始与结束、工作状态、文本增量、文本快照、回复完成、角色指令、审批请求/取消/结果、可选音频、可见错误。

能力从现有布尔字段演进，但先保留兼容映射。建议显式表示：characterTools、statusEvents、assistantText、sessionSelection、sendInput、cancelTurn、approvalNotifications、approvalDecisions、receiveAudio、screenshots。审批通知与审批决定不可合并为一个能力。

| 入口 | 按当前代码可规划的能力 | 需要另行证明的能力 |
| --- | --- | --- |
| DeepSeek Harness | 角色工具、状态、公开回复、已有审批委托、人设注入 | 可靠会话发现、双向输入、取消轮次的具体接口 |
| 通用 MCP 角色工具 | 角色指令与短通知 | 会话观察、持续回复、审批事件和双向输入 |
| MaiBot | 已有文字输入、公开回复、情绪/动作/控件、后端音频 | 输出与输入轮次的严格关联、取消、稳定错误事件 |

这是根据本地接入代码拟定的表，不是对所有宿主版本的能力保证。真实插件必须协商并报告能力；未证明能力返回 unavailable。

### 4.3 流式文本规则

- text.delta 仅携带本次新增文本；text.snapshot 替换同一回复的完整文本；reply.done 只结束回复。
- 回复键至少包括 instanceId + sessionId + replyId。旧请求的 done、error 不关闭新请求。
- 每个回复内部使用 sequence 去重和排序；并行 HTTP 投递不能假定天然保序。插件端建立按流串行队列或合并快照，避免每个 token 建立一个无限并发请求。
- 清除内联表情标记时保留跨 chunk 解析缓冲；未完整的 [uta:...] 不泄露到气泡，也不吞掉正常文字。
- 正文保留换行、缩进、空白和 Unicode；短标签仍可使用现有压缩空白的 sanitizeText。不能把角色通知清洗规则直接用于代码回复。
- 当前 600 字符截断和 8KB 请求体是现有通知通路约束。完整回复采用有界分片与总长度限制；显示摘要与完整正文分开，截断要明确提示。
- 不保留无限流历史；超长内容、断线和积压必须有明确丢弃或恢复策略。

### 4.4 输入、状态与审批规则

反向输入由 renderer 提交绑定标识和文本，主进程核对能力、当前连接与会话后发送。结果区分 accepted、unavailable、rejected、failed；不能把 TCP 已发送写成“模型已接受”。输入不自动切到其他会话。

工作状态和角色表情分离。任务状态来自宿主事实，表现映射由 Uta 配置。断线、失败、取消和结束均能退出 thinking/streaming；文本口型与真实音频 speaking 分开。

审批复用宿主原有审批服务，不允许插件直接执行动作。桌宠卡片只回传一次性用户决定，宿主验证请求仍有效后执行。复合标识至少包含宿主实例、会话和 requestId。超时、重复点击、宿主取消、切换绑定、渲染刷新、Uta 退出均不能留下悬挂审批。

不支持桌宠决定的入口只显示提醒并交回宿主。窗口临时解除穿透需有引用计数/统一恢复逻辑，多张卡片、取消和异常路径都恢复用户原设置。

### 4.5 兼容演进

先保留现有 /command、/context、/approval/ask、/approval/cancel；新增版本协商与实例登记时增加明确的新版本载荷或路由，不悄悄改变旧字段语义。

旧客户端无会话的角色指令可作为 legacy-tools 接入，显示“未绑定会话”。旧版无身份的回复、状态或审批不能自动归属当前会话；仅在用户显式选择兼容模式后有限支持，且不同时开启多个来源。

主进程运行时重启后端口和 token 变化，插件重新读取端点文件并重新登记。旧实例事件和迟到请求不作用于新绑定。

## 5. 分阶段实施计划

顺序原则：固定现场 → 统一链路 → 完善 Harness → 接回 MaiBot → 完善使用体验 → 可选语音 → 发布验收。每阶段单独验收，不以“文件搬完了”作为完成标准。

### 5.1 固定源码基线与协作边界

**目标：** 为多人协作建立可回溯的现状，避免迁移建立在不断变化的散文件上。

**任务：**

1. 核对 Uta 当前源码与 Harness 插件的实际激活版本，记录宿主版本、测试命令、运行模式和已知问题。
2. 在维护者审阅后建立源码基线提交。仅提交需要分发/维护的源码、模型示例和文档，不把 node_modules、out、日志、临时交接文件、tsbuildinfo 或个人配置纳入。
3. 核对 .gitignore、安装依赖来源和锁文件现状；选定一种包管理方式并生成锁文件。之后 CI 使用冻结依赖安装。
4. 与修复 MaiBot Deskpet 的智能体明确交接：交付修复提交、变更文件、测试证据；Uta 从已验收提交引入共享修复。
5. 建立 docs/HANDOFF.md 与当前任务清单，记录开始时的工作区、已启动进程、端口和待验证点。
6. 在 app/ 的真实根目录识别权威文件位置；检查空的或历史 app/plugin、app/docs 是否为遗留目录，不递归删除未知内容。

**涉及范围：** .gitignore、依赖锁文件、docs；不改变用户交互。

**完成条件：**

- 能从一个明确源码提交恢复项目；运行时生成物不污染源码提交。
- 完成当期 npm test、npm run test:plugin、npm run typecheck、npm run build，并记录实际数量与失败点。
- README、MIGRATION 和 Harness HANDOVER 的历史信息与当前现场分别标注。
- 每个后续任务有唯一负责人和明确写入范围。

**回滚：** 文档与忽略规则可单独撤回；不得用 reset --hard 或批量删除恢复现场。

### 5.2 统一宿主事件、会话绑定与运行时链路

**目标：** 所有宿主事件经过同一处理链，舞台不再解释宿主协议。

**任务：**

1. 评审并落地共享事件、能力、绑定与请求结果类型，增加 schema 校验和正常/异常契约夹具。
2. 主进程新增 Host Gateway、实例登记与活动绑定管理；保留已有 HTTP 传输与认证实现。
3. runtime-push 驱动将现有 RuntimeCommand 转成统一事件。现有协议入口保留兼容，不直接修改 Pinia。
4. 新增固定的事件订阅、获取绑定、绑定选择和反向输入 IPC；所有有副作用的 IPC 核验主窗口主 frame 及载荷。
5. renderer 新增 HostClient，绑定信息使用可订阅/响应式状态；切换顺序为解除旧订阅、停止旧轮次副作用、更新绑定、建立新订阅、同步模型上下文。
6. 将 applyRuntimeCommand()、applyAgentWorkingState() 的宿主业务部分移入统一控制器，舞台保留模型执行函数，通过 deps 注入。
7. 回复支持 delta 与 snapshot 两种明确语义，停止使用通知文本清洗器处理正文；修复累计文本被追加问题。
8. 状态区分“Uta 本机桥可用”“插件已登记”“会话已绑定”“宿主忙碌”，不显示虚假的已连接状态。
9. 无活动绑定仍允许模型展示与本地预设编辑；fake 适配器作为开发模式显式启用，不静默冒充真实宿主。

**现有文件重点：** runtime-bridge.ts、runtime-commands.ts、main/index.ts、preload/index.ts、renderer/env.d.ts、services/host/、services/adapters/、DeskpetStage.vue、stores/chat.ts。

**拟新增验证：** host-gateway、session-binding、host-client-lifecycle、reply-stream 的测试；名字是建议，实施时按项目规范命名。

**完成条件：**

- Runtime 与 fake 的同一事件夹具产生一致状态；主舞台不包含 Harness/MaiBot 消息类型分支。
- “你”增量加“好”增量得到“你好”；“你”快照再“你好”快照最终只有“你好”；done 不再追加全文。

**迁移与回滚：** 新旧入口通过明确内部兼容层过渡；每个检查点保持旧 Harness 插件可有限使用。只有统一链路回归通过后才删除旧分支。

### 5.3 完善 DeepSeek Harness 接入与审批恢复

**目标：** 把已存在的 Harness 实现变成可稳定使用、可说明能力范围的首个完整适配器。

**任务：**

1. 核对真实宿主的版本与事件载荷，更新纯函数解析器及兼容测试。不要从其他宿主或过时交接文档猜测接口。
2. 按实例与会话登记插件，公开可获得的会话元数据；无会话发现接口时通过用户指定/已观察会话登记，不伪造全量会话列表。
3. 插件采用统一事件信封，完成回复序号、发送队列、流式标记缓冲和 assistant/message 兜底去重。
4. 将单文件插件逐步拆为 endpoint-client、stream-parser、session-events、approval、persona-context、character-tools；保留相同安装入口。
5. 三个开关分别控制 RP 注入、正文气泡同步、可选语音。关闭 RP 时不再注入该 section/context；离线时遵守已配置的回退选择。
6. 人设与模型上下文缓存按实例/绑定与修订号失效；模型切换后新预设分组生效，不覆盖用户自定义人设。
7. 审批回传使用宿主当前合法请求，处理取消、超时、重试、重复点击、离线和切换。拒绝与转交不能混为“允许”。
8. 若桌宠交互审批决策尚未获确认，先以提醒加转交模式验收，保留卡片代码但不扩大权限。
9. 对不支持的 sendInput/cancelTurn 保持明确不可用。双向输入作为独立小任务，在核实官方或本机宿主实现后再启用。

**涉及范围：** deepseek-harness/src/、runtime bridge/approval 模块、ApprovalCard.vue、RP 设置与模型上下文同步。

**真实宿主验收脚本：**

- 启动 Uta 与 Harness，确认插件已登记，绑定一个会话。
- 完成一轮普通回复、一轮调用工具、一轮失败/取消，核对状态和回复只出现一次。
- 创建两个并行会话，非活动会话不得改变当前角色或卡片。
- 触发审批并分别批准一次、拒绝、转交；再测试宿主取消和桌宠关闭。
- 关闭 RP、关闭正文同步，分别验证主窗口语气与桌宠内容的变化。
- 宿主或 Uta 重启后重新登记；不使用旧 token、旧卡片或旧轮次。

**完成条件：** 以上流程有实际宿主证据；测试替身通过与真实宿主通过分别记录。桌宠不可用时宿主主流程能继续或回退，不被通知失败阻塞。

**回滚：** 暂停正文/审批增强，回到角色工具与短通知；保留宿主原生审批和主窗口输入。

### 5.4 接回 MaiBot 为可选后端

**目标：** 现有 MaiBot 用户能通过 Uta 使用文字、角色指令和已有回复能力，Uta 核心不重新引入 MaiBot 专属依赖。

**实施策略：** 先保持 MaiBot SDK 插件与既有 WS 协议兼容；在 Uta 主进程增加 maibot-ws 驱动。不要为了“全部走 HTTP”同时重写两端。

**任务：**

1. 以另一个智能体验收后的插件提交为输入，记录来源 SHA、SDK/宿主版本、兼容范围与相关修复测试。
2. plugin/plugins/maibot/ 明确维护 SDK 插件、manifest 与接入文档；若暂时仍从原仓库分发，也明确权威来源，禁止长期手工维护两份 plugin.py。
3. Uta 保存 WS 地址与令牌的后端配置；凭证留在主进程，以受保护的系统存储保存，日志和 UI 脱敏。
4. 驱动实现认证、连接、重连退避、心跳、关闭和消息校验，将 input/output/state/sys 消息转换为统一事件。

6. 现有入站 request_id 与出站重新生成的回复 ID 不必然对应。先保持独立的输入确认和回复 ID；若要关联轮次，需要验证网关 metadata 能力或版本化扩展，不能靠猜测配对。
7. 模型情绪、控件、预设经共同模型上下文发布；仅活动 MaiBot 绑定将能力上报该后端，重连后补发。
8. SDK 注入拒绝、超时、断线和 TTS 失败转换为可见错误；思考状态有明确退出和诊断，不无限等待。
9. 后端提供的音频经媒体接口接收；后续 Uta TTS 开启时采用唯一播报策略，避免同一回复播两遍。
10. sys:env 的 Python 路径只留在 MaiBot 配置/可选桥启动功能中；不作为所有宿主的统一运行时授权事件。没有服务管理需求时只忽略并记录兼容事件。
11. 默认不恢复全部 Python 服务自启。是否托管 STT/TTS 桥作为媒体阶段单独决定。
12. 原 MaiBot Deskpet 保持既有配置与发布渠道，先提供试用接入说明，再进行用户迁移。

**涉及范围：** 新 main/host/drivers/maibot-ws、共享协议、后端设置、插件包装与文档。原 renderer/useWebSocket.ts 只作为迁移参考，不整体搬回。

**完成条件：**

- 真实 MaiBot 完成文字输入、回复、情绪/动作/控件、重连能力同步。
- MaiBot 未启动、令牌错误、网关注入被拒、插件卸载均能恢复，Uta 仍可显示和编辑角色。
- Harness 与 MaiBot 可分别登记和选择；非活动宿主事件不会污染活动会话。
- 旧模型/立绘包可以加载；普通用户数据迁移不会覆盖原目录。
- 插件能够在约定 SDK 版本加载，且原正式版用户不因 Uta 发布被迫升级。

**回滚：** 禁用 MaiBot 注册项而保留 Harness；用户继续使用原 MaiBot Deskpet 安装版。迁移采用复制并保留来源，失败时不删除旧数据。

### 5.6 接入可选语音与音频口型

**目标：** 语音对不同宿主复用，默认关闭，取消和切换后可恢复。

**顺序：** 先播放器与后端音频，再一种文本合成提供方，最后转写和 PTT/VAD。不同时实现全部云平台。

**任务：**

3. 支持 MaiBot 后端音频，选择 host-audio、uta-tts、off 中一个策略。明确每条回复是否可播报、是否已播报。

9. 若需 Python 本地桥，单独引入服务提供方模块和解释器确认，不恢复默认跨宿主自启，进程所有权与退出验证保持原项目标准。

**完成条件：**

- 模拟环境覆盖超时、取消、切换、旧回复、格式错误、队列溢出和恢复。
- 显式进行真实设备验收；测试替身通过不等同于硬件通过。

- 云端调用由用户配置与触发；测试不默认请求收费接口。

**回滚：** 独立关闭媒体提供方；文字、角色与宿主链路继续使用。

## 7. 验收矩阵与检查方法

### 7.1 自动化与真实验收分层

### 7.2 必须覆盖的关键场景

| 场景 | 预期 |
| --- | --- |
| Uta 未运行时宿主通知 | 可读的不可用或忽略结果，不阻塞宿主主任务 |

| 相同 eventId 重试 | 不重复气泡、动作、播放或审批 |
| 两个宿主同时在线 | 只有活动绑定驱动任务表现 |
| 同宿主两个会话 | 非活动会话不改变当前回复或工作状态 |
| 切换后旧 done/error 到达 | 不结束新轮次、不产生错误气泡 |
| 流式快照、增量、兜底消息同时出现 | 正文准确、只显示一次 |
| 标记跨 chunk、代码块与中文正文 | 标记解析正确，正文缩进与换行保留 |
| 发送失败、SDK 拒绝、网关超时 | 退出等待状态，提示明确且可重试 |
| 宿主无输入/取消能力 | UI 不宣称支持；请求明确返回不可用 |
| 审批被宿主取消或用户切换 | 卡片关闭，迟到点击无效，不被执行 |
| Uta 刷新/退出、卡片超时 | 请求结算或交回宿主，穿透设置恢复 |
| 模型更换、预设不存在 | 上下文更新，未支持指令有明确结果 |
| 模型路径含 #、%、空格、中文 | 可往返解析并加载 |
| 预设写入失败/资源目录只读 | 用户设置写 userData，错误可见 |
| 语音取消与旧转写返回 | 新录音可开始，旧文本不发送 |
| 后端音频与 Uta TTS 同时可用 | 只按选定策略播报一次 |
| 隐藏、穿透、多屏与 DPI 改变 | 日常入口可恢复，审批不丢失 |
| 安装升级与旧数据迁移 | 用户模型/预设保留，失败不覆盖来源 |

## 8. 版本与优先级建议

以下是范围建议，不是发布日期承诺。版本号由维护者在阶段验收后决定；如果拆分更小，可以使用预发布版本。

| 候选版本 | 交付重点 | 发布门槛 |
| --- | --- | --- |
| 0.2.x 统一运行时内测 | 统一事件、绑定、正确流式文本、真实连接状态 | 自动化回归与 Harness 基本链路 |
| 0.3.x Harness 体验内测 | 会话隔离、人设开关、审批策略与恢复 | 实际宿主完整流程 |
| 0.4.x 多宿主预览 | MaiBot 可选接入、能力驱动设置、基础迁移 | Harness + MaiBot 分别及切换验收 |
| 0.5.x 使用体验测试 | 首次使用、持久化、安装包和用户文档 | 干净安装与升级 |
| 0.6.x 可选语音测试 | 一种 TTS、播放器，按需要加入转写 | 取消恢复与真实设备 |
| 1.0 候选 | 冻结支持范围、兼容矩阵、回退和维护规则 | 首发功能的完整发布检查表 |

不强制等语音完成才发布稳定的无语音版本。若用户最重视跨宿主文字与角色表现，可以在多宿主与安装验收完成后先发布；语音作为后续功能。

优先级顺序：统一事件/流式正确性 → 活动绑定/生命周期 → Harness 真实验收 → MaiBot 接回 → 首次使用/数据与安装 → 可选语音 → 更多宿主。

工作量建议以任务为单位估算：协议、Gateway、Harness、MaiBot 各为中到大范围任务；语音与安装升级需要单独验收窗口。没有核实宿主接口和执行资源前，不按日期承诺完成时间。

## 9. 主要风险与处理办法

| 风险 | 处理办法 |
| --- | --- |
| 两个项目继续复制前端导致修复分叉 | 记录通用修复来源，逐步以 Uta 为通用功能权威；兼容期结束再决定公共包 |
| 共享令牌被误认为每宿主权限隔离 | 明确可信插件范围；身份从连接登记建立，需要隔离时再引入独立客户端凭证 |
| 宿主事件/SDK 升级 | 兼容矩阵、固定测试版本、真实契约夹具，未知字段不能变成隐式能力 |
| 纯角色工具被包装成完整后端 | 能力声明如实展示，角色工具接入允许无会话，不能伪造内容订阅 |
| 多会话状态与审批混杂 | 单活动绑定、复合 ID、非活动事件过滤、切换结算 |
| 流式请求并发造成乱序/重复 | 按回复串行队列或快照合并、sequence、幂等，明确积压上限 |
| 拆模块造成现有交互回归 | 先抽业务控制器，保留模型引擎，通过正常/最坏场景逐步迁移 |
| RP 影响代码任务表达 | 独立开关、保留技术准确性，关闭时不注入，不由桌宠擅自改主回复 |
| 审批承担超出宿主允许的权限 | 只回传用户决定，宿主检查请求有效性，支持即时关闭与原生回退 |
| 安装版资源与 dev 路径不同 | 打包资源清单、路径空格、用户目录与真实安装验证 |
| 模型与运行时许可清单缺失 | 发布前整理代码、模型、Live2D 核心的来源和声明，维护者确认分发范围 |
| 尚未提交的并行改动被误收录 | 提交前检查暂存区，路径级提交，不覆盖共享交接文档 |
